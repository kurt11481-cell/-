# 주식 분석·전략·알림 프롬프트 최적화 검토

## 최종 요약

기존 `권장 통합 프롬프트 v2`의 분석 철학, 생각의 나무 기반 주식 지침, 옵션 분석 지침·코드, 매매시점 자동 알림 설계를 하나의 거대한 프롬프트로 합치지 않고 역할별 정책·상태·실행 코드로 분리했다. 결과물은 한국어 정책 원문인 `RECOMMENDED_INTEGRATED_PROMPT_V3_KO.md`, 영어 Codex Skill인 `manage-us-stock-strategy`, 그리고 읽기 전용 자동 알림 시스템으로 구성된다.

이 구조의 핵심은 더 많은 숫자를 내는 것이 아니라, 검증되지 않은 숫자와 상태가 매매 후보로 승격되는 경로를 차단하는 데 있다.

## 검토한 입력

- `gpt 주식 지침(생각의 나무)_rev.txt`: 기업·섹터·기술·시나리오 분석 체계
- `미국주식 옵션데이터 분석 (1).txt`: 옵션 데이터 수집·Greeks·OI·Max Pain·보고 형식
- `us_option_ext (1).py`: Yahoo 옵션 체인 수집 및 계산 코드
- `매매시점 자동 알림.txt`: 보유수량, 단계별 전환 수량, 가격구간, 알림 주기와 등급
- 기존 대화의 `권장 통합 프롬프트 v2` 방향: 결론 우선, 근거 검증, 신규 진입 관점, 반도체 인프라 특화

## 유지·강화한 요소

### 결론 우선 구조

모든 최종 답변과 세부 항목은 판단을 먼저 제시한 뒤 근거를 붙인다. 다만 근거가 부족하면 강한 결론 대신 `Not verified`, `Wait`, `F — Data/state error`를 사용한다.

### 신규 매수 의사결정 게이트

신규 매수는 다음 순서를 반드시 통과한다.

```text
증거 무결성
→ 투자논리 유효성
→ 현재 밸류에이션
→ 기술적 진입조건
→ 포트폴리오 집중도·포지션 크기
```

앞 단계가 미검증이면 차트가 강하더라도 최종 판정을 매수로 올리지 않는다. 투자기간이 없으면 장기 적립과 단기 스윙을 분리한다.

### 반도체 인프라 특화

제품 발표, 샘플, 인증, 디자인윈, 주문, 양산, 매출인식, 현금회수를 구분한다. AI CAPEX, 부채조달, GPU·ASIC·HBM·스토리지·광통신·전력·냉각의 병목을 공급망 계층별로 본다. 수혜 강도와 현재 주가의 가격 매력을 별도로 평가한다.

## 제거·수정한 요소

### 강제 명령 단계 제거

`추가 검색 → 심층 추가 검색 → 추론 시작` 같은 대화식 잠금은 Codex 에이전트에 불필요하므로 제거했다. 한 번의 요청에서 필요한 범위까지 검증하되, 데이터가 없으면 멈추도록 바꿨다.

### 내부 사고과정 출력 제거

생각의 나무는 내부 탐색 방식으로만 사용하고 숨은 추론을 장문으로 노출하지 않는다. 사용자에게는 대안, 채택 이유, 반증조건, 남은 불확실성만 제공한다.

### 임의 점수·확률·목표가 제한

근거 없는 `8.8/10`, 임의 시나리오 확률, 단일 PER로 만든 정밀 목표가를 금지했다. 확률은 검증 가능한 모델·입력이 있을 때만 사용하고, 아니면 조건부 시나리오로 표시한다.

### 검색 부재를 안전 신호로 보지 않음

검색에서 회계조사·희석·소송이 나오지 않았다는 이유만으로 `깨끗함`을 선언하지 않는다. 확인 범위와 미검증 범위를 분리한다.

## 옵션 모듈의 주요 교정

- Vanna 부호를 `-exp(-qT) × φ(d1) × d2 / σ`로 교정하고 유한차분 테스트를 추가했다.
- Yahoo OI는 보유 주체·롱/숏·딜러 방향을 알 수 없으므로 Call-minus-Put 값은 휴리스틱 프록시로만 표시한다.
- Max Pain은 방향성 자석이 아니며, 25-delta strike는 예상 가격범위가 아니다.
- 양방향 bid/ask, spread, IV, OI, 명시적 `REGULAR` 계약만 Greeks와 Max Pain에 사용한다.
- `LIMITED` 만기보다 `PASS` 만기를 우선 탐색하고 요청한 만기 수가 모두 통과해야 연구 보고서를 정상 판정한다.
- Yahoo bid/ask에는 검증 가능한 체인 시각이 없으므로 자동 방향성 알림 자격을 영구 차단한다.
- 공식 완료 거래일과 직접 출처를 외부에서 검증해 넘기지 않으면 연구 보고서도 적격 판정을 받지 못한다.
- HTTP 401/429, 빈 응답, 스키마 오류는 숫자를 추정하지 않고 실패로 종료한다.

## 자동 알림 모듈의 주요 교정

- `portfolio_state.json`은 보유·현금·체결의 진실원천이며 자동 실행에서 읽기 전용이다.
- `alert_runtime_state.json`만 처리 세션, 이벤트 상태, 전송 ID, 감사 이력으로 원자 갱신한다.
- 공식 거래일, 직접 출처, 검증시각, 예상 세션, 동일 완결봉을 확인하기 전에는 F등급으로 동결한다.
- 현재 실행 대비 오래된 시장·캘린더 스냅샷과 정책 기한을 넘긴 브로커 보유상태도 F등급이다.
- 정확한 NAV 여부는 `account_value_is_estimate=false`가 명시된 경우에만 인정한다.
- 가용현금이 미확인인 연결 바스켓은 매수뿐 아니라 매도 다리도 최대 B등급이다.
- 미체결 매도대금과 SGOV는 결제된 현금으로 계산하지 않는다.
- 이벤트 지속 상태와 당일 전송 ID를 분리해 같은 등급의 반복 알림을 억제한다.
- 단일실행 잠금, 경로 별칭 차단, 원자 저장으로 동시 실행과 상태파일 덮어쓰기를 방지한다.
- 어떤 경우에도 브로커 주문을 전송·예약하거나 가격 접촉을 체결로 간주하지 않는다.

## 운영상 남은 입력

2026-07-31 15:48 KST 사용자 확인으로 정확한 브로커 현금과 신규매수 가용현금은 모두 USD 0, 보유상태는 SOXL 99주와 MVLL 396주로 갱신됐다. 이는 기존 배당·코어 ETF 단계별 전환정책과 맞지 않아 해당 단계를 동결했다. SOXL·MVLL용 레버리지 위험정책이 별도 승인되기 전에는 실행 후보를 만들지 않는다. 또한 최초 추세확인 공식은 `provisional_v1_requires_forward_test`이므로 일정 기간 모의운영 후 오경보·누락률을 검토해야 한다.

옵션 Yahoo 엔드포인트가 HTTP 401을 반환할 수 있고 bid/ask 자체의 체인 시각도 제공하지 않는다. 옵션을 자동 알림에 활용하려면 합법적인 읽기 전용 데이터 소스 또는 사용자가 제공한 시간표시 체인 스냅샷이 별도로 필요하다.

## 권장 운영 순서

1. 완료: 정확한 현금·가용현금·보유수량·평균원가와 기준시각을 사용자 확인으로 반영했다.
2. SOXL·MVLL의 투자기간, 최대 허용손실, 감축·청산 원칙과 비중 상한을 확인해 새 정책 버전을 승인한다.
3. 반복 알림을 최소 20개 미국 거래세션 동안 모의운영한다.
4. A/B/F 발생 사유와 거짓 양성·거짓 음성을 기록한다.
5. 추세공식과 가격구간 변경은 자동 반영하지 말고 버전 후보로 제시해 사용자 승인을 받는다.
6. 옵션은 독립 연구 모듈로 유지하고, 체인 시각이 검증되기 전까지 현물 매매 알림의 승격 근거로 사용하지 않는다.
