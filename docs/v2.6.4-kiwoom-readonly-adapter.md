## Runtime boundary

The strategy process sends only a ticker, an allowlisted read-only operation,
the completed-session date, a raw/adjusted flag, and a false FX flag. The
external official runtime loads credentials inside its own process and returns
only normalized allowlisted fields. Extra request keys fail closed. Output is
re-sanitized by the parent process.

Allowlisted Kiwoom calls are OAuth health, U.S. exchange lookup, stock list,
stock lookup, ETF/ETN list, and U.S. daily chart. Any order, modification,
cancellation, credit, FX-order, or account-mutation target returns
`KIWOOM_ORDER_ENDPOINT_BLOCKED`.

## Identity and price basis

U.S. exchange mapping is derived from Kiwoom identity evidence. Unknown or
ambiguous identity does not fall back to an exchange. SOXL therefore resolves
to `NY` only when the sanitized Kiwoom evidence says so.

Raw and adjusted series are separate immutable objects:

- Raw: `upd_stkpc_tp=0`, `exrt_appl_tp=0`.
- Adjusted: `upd_stkpc_tp=1`, `exrt_appl_tp=0`.

FX-applied prices are rejected. Raw close comparison uses the already-approved
`max(USD 0.05, 0.10% of Primary close)` tolerance and treats a decision-boundary
flip as conflict.

## Failure and output safety

One ticker failure remains ticker-local. HTTP 429 and authentication failures
open the circuit without retry storms. Other bounded retries and request pacing
come only from `workspace/policies/kiwoom-rate-limit-policy.json`.

Normalized output must validate before an atomic write and must live below
`workspace/outputs`; canonical portfolio and policy paths are protected from
aliasing. Every snapshot records the official runtime commit, completed-session
lock, portfolio-state input hash, zero operational Shadow increment, and
`order_authority=false`.
