# v2.5 Selective Evidence and Broker Snapshot Migration

## Starting point

The implementation started from `main` commit
`3ef389c04d77a0c386be7b7a7a278b6d6162552b` on the isolated branch
`feature/v2.5-selective-evidence-broker-snapshot`. The pre-change suite passed
146 tests. Pre-existing workspace artifacts in automation runtime, `repo_tree.txt`,
and the 2026-08-12 portfolio-strategy output were preserved and excluded from
the feature commit.

The strategy version remains `2026-08-05-v4`. No hard-risk threshold, rule ID,
staged quantity, leverage approval, short-sale authority, or order authority
changed.

## Selective completed-close evidence

v2.5 separates primary OHLCV validation, technical recomputation, and
independent completed-close evidence. yfinance can produce
`PRIMARY_VALIDATED`, never official evidence. Routine HOLD/WATCH/NOT_READY and
ADD_ON_WATCH results create no independent request. READY, material deterministic
NEAR_TRIGGER, add/reduce/exit review, hard-risk, decision-boundary, and optional
canary cases enter a deterministic queue.

Missing queued evidence leaves opportunity quality visible and sets execution
to `VERIFICATION_PENDING`. An empty queue is `NOT_REQUIRED`. A validated direct
conflict is ticker-local. Web acquisition is `CODEX_WEB`; the actual domain and
source type remain the evidence provider. Yahoo-origin pages and search snippets
are rejected. Direct-close tolerance is `max(USD 0.05, 0.001 * primary close)`.

## Leveraged confirmation

The canonical registry now records `SOXL -> SOXX` as `DIRECTION_ONLY` sector
context and `MVLL -> MRVL` as supplemental `DAILY_MULTIPLE` context. Neither
proxy substitutes for a direct product close. No hidden one-percent live
tolerance was activated; unapproved tracking tolerance remains shadow-only.

## Broker reconciliation

The new pipeline supports image-bundle metadata, structured extraction,
validation, proposal creation, explicit confirmation, concurrency checks,
atomic state replacement, and before/after audit hashes. Upload/extraction alone
cannot mutate portfolio state. Scope enforcement prevents CASH_ONLY from
replacing holdings and POSITION_ONLY from implying portfolio completeness.

Raw images are Git ignored. Broker display prices are reconciliation context,
not market evidence. Margin buying power and unsettled proceeds cannot become
available cash. No OCR/cloud dependency was added; the committed acceptance
artifact uses a sanitized test fixture and explicitly states that no source
image was visually parsed.

## Shadow runtime migration

The migration copies existing delivery/dedup metadata into separate
trade-review, holding-review, price-verification, broker-snapshot-request, and
confirmation-required namespaces. It does not copy holdings, cash, average cost,
fills, or orders, and it prohibits replay of historical deliveries. Live
runtime state is not overwritten.

## Deployment boundary

This upgrade is shadow-only until its feature commit passes the full regression
suite and the installed Skill hash gate. Scheduled tasks are not activated or
modified. Live portfolio state and existing runtime files remain outside the
feature change.
