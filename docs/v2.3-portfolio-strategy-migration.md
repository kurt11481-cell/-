# V2.3 Portfolio Strategy Orchestrator Migration

## Scope

V2.3 adds a read-only portfolio strategy orchestration layer above the existing
operational holding-risk engine and the v2.2 tactical opportunity radar. It does
not replace either authority source and does not add brokerage execution.

The combined workflow is:

```text
canonical portfolio state
  -> operational holding-risk evaluation
  -> per-holding strategy review
  -> v2.2 tactical opportunity radar
  -> cash-bucket and redeployment review
  -> deterministic portfolio gate
  -> Korean-facing human-review card
```

## New Contracts

- `holding-strategy.schema.json` defines the exact holding strategy and separate
  execution states.
- `capital-redeployment-plan.schema.json` separates verified cash, projected
  sale proceeds, and unsettled or unconfirmed proceeds.
- `portfolio-strategy-report.schema.json` combines the holding, tactical, event,
  funding, and approval domains without collapsing their statuses.
- `holding_strategy_runtime.json` stores transition and dedup metadata only.

## Holding Strategy Authority

The orchestrator consumes the existing operational risk result. It does not
recalculate maximum-loss or EMA reduction rules. Hard risk is evaluated before
return-seeking research. Exact reduction quantity is surfaced only when the
operational timing engine provides a current deterministic tranche and
provenance. Otherwise quantity remains `null`.

Holding strategy states are:

`HOLD`, `ADD_ON_WATCH`, `ADD_REVIEW`, `REDUCTION_REVIEW`, `EXIT_REVIEW`,
`STRATEGY_REFRESH_REQUIRED`, and `DATA_BLOCKED`.

Execution state remains independent. Research can never grant cash, quantity,
leverage, or order authority.

## Capital Redeployment

Only broker-verified available cash contributes to execution purchasing power.
Projected sale proceeds require an exact deterministic review quantity and a
validated current completed-session price. They remain a projected funding
scenario and cannot fund a current purchase. Unsettled or unconfirmed proceeds
remain separately visible. No bucket is double-counted.

The tactical research universe remains exactly:

`MVLL`, `SOXL`, `NBIS`, `BE`, `TOST`, `NOW`, `FSLY`.

Candidate research eligibility still does not equal new-buy approval.

## Automation

`stock-strategy-system/PORTFOLIO_STRATEGY_AUTOMATION_PROMPT_EN.md` defines a
single combined morning review. It is a Codex read-only decision-support run,
not a Windows Task Scheduler job and not an order workflow. Runtime writes are
restricted to shadow metadata under `workspace/outputs` unless a separately
approved operational automation contract is used.

## Compatibility and Safety

- The canonical `portfolio_state.json` is an input and is never written.
- The v2.2 opportunity radar remains independently visible when portfolio risk
  blocks execution.
- Event coverage, market data, and tactical data have separate statuses.
- Missing independent close evidence fails closed.
- Every report declares `order_authority: false`.
- The existing alert-policy and technical-validator authorities are preserved.
