### 1-1 TradingAgents (TauricResearch) — 여러 LLM이 증권사 조직을 흉내 내는 연구 틀
- 흐름: 분석가 4명(기본·심리·뉴스·기술) → 강세/약세 연구원 토론 → 연구 관리자 → 트레이더 → 위험 분석가 3명 → 포트폴리오 관리자가 최종 등급. 그래프 LLM 역할 최대 12개(tradingagents/graph/setup.py 126-155행) + 지난 결정을 정산할 때 결정마다 반성을 쓰는 LLM 1개(Reflector, trading_graph.py 106·314행).
- 판: v0.7.1(2026-10-27, CHANGELOG.md 9행), Apache-2.0, 스타 약 118k(GitHub 페이지 표기).
- 주문: **없음.** README 110행은 "승인되면 모의 거래소로 보내 실행"이라고 쓰지만, 의존성(pyproject.toml)에 증권사 SDK가 없고 portfolio.py 9-11행이 "증권사·주문 경로를 뜻하지 않는다"고 적는다(소스 전체를 연 것은 아님 — 8절).
- 키·비용: LLM이 필수다. API 키(기본값 OpenAI, default_config.py 92-94행. Claude는 ANTHROPIC_API_KEY로 구독과 별도 과금, README 167행) 또는 ChatGPT 구독 로그인(README 188행) 또는 로컬 Ollama(README 192행). 1회 실행 비용은 README에 없음 → **확인 필요**.
- 자료: 가격 기본 yfinance(default_config.py 159행), 재무 SEC EDGAR(키 없음, 연락 이메일은 권장이고 기본값이 대신 보내짐, README 308행), FRED·Alpha Vantage 키 선택.
- 외부 호출: 위 자료·LLM 외에 대화형 CLI가 시작할 때 하루 1회 새 판을 확인한다(README 36행·CLI 절, `TRADINGAGENTS_NO_UPDATE_CHECK=1`로 끔).
- 주의: "연구용, 투자 조언 아님"(README 78행), 같은 종목·같은 날도 실행마다 결과가 다름(README Reproducibility 절), "백테스트 결과는 공개 수치와 같다는 보장 없음"(README 405행). 보유·현금을 넣으면 판단에 반영되는데(README 316행) 그 내용이 외부 LLM 회사로 간다.
- 0.4.0~0.6.0 변경(CHANGELOG 9-330행)은 하나씩 대조하지 않았다. 대조한 것은 0.7.0의 "결정 다음 첫 종가부터 채점" 1개다(4절).

### 1-2 Vibe-Trading (HKUDS) — 말로 묻는 투자 연구 + 백테스트 + 증권사 연결 + 자동매매
- 구성: 연구 에이전트, 백테스트 엔진, 스킬 90개, 여러 에이전트 팀, 자료원 29개, MCP 도구 83개(README 1927행, 셈 83), 웹·데스크톱 앱, 메신저 연결, 예약 연구, 내 매매 기록 분석(Shadow Account), 증권사 19곳 연결, 모의매매, 실전 자동매매 실행기.
- 판: v0.1.18(2026-10-21, CHANGELOG.md 139행. README 74행은 10-22), MIT, 스타 37.1k·커밋 3,506(페이지 표기), 개발 단계 "Beta"(pyproject classifiers). 10/23~10/29 매일 '미출시' 수정이 올라옴(README News).
- 주문: **있음.**
  - "원하면 직접 승인한 증권사(예: 로빈후드 Agentic Trading)로 자율 매매"(README 402행).
  - 증권사 표(README 488-563행): 실전 주문 가능 프로필 alpaca·binance·etoro·futu·mt5·okx·tiger `live-trade`, `robinhood-live-mcp`(조건 "mandate required").
  - 실전 실행기: 기본 15분마다 AI 판단, 하루 26회·100만 토큰 한도(README 2191행~).
  - 면책: "증권사 매매 기능은 실험 단계이고 실제 증권사 계좌로 검증하지 않았다"(README 2758행).
  - 자체 변경 기록에 안전장치 결함 이력: 실전 관문이 열린 채 통과된 결함 2건(2026-08-25, README 181행), 자기 동작을 건너뛴 긴급 정지(08-29, 177행), 아무것도 확인 안 하고 PASS한 감사(09-06, 169행), 테스트는 통과하는데 실주문을 전부 거절한 관문(09-17, 150행).
  - **키움 없음**: 연결 목록(agent/src/trading/profiles.py 9-27행)에 한국은 KIS·Toss·Upbit(KIS·Upbit는 모의 주문 프로필만).
- MCP: write_file·read_file·web_search·trading_*(조회)·paper_trade_step·qveris_execute(유료)·run_swarm 등 83개(README 1927행). Vibe-Trading 안의 에이전트가 다른 MCP 서버를 불러 쓰는 기능도 있다(README 2087행).
- 키·비용: LLM 키 필요(기본 OpenRouter + deepseek-v4-pro, README 1295행). Claude Code 로그인으로도 돌릴 수 있는데 단계마다 `claude -p` 1회씩이라(README 1126행) 사장 구독 사용량을 쓴다. 자료는 무료 출처(yahoo·stooq·eastmoney·akshare 등) 기본, QVeris는 유료(추천인 링크 포함, README QVeris 절).
- 보안: 키를 agent/.env에 저장하고 웹 설정 화면이 .env를 고친다(README 1752행). AI가 만든 백테스트 코드를 로컬 파이썬으로 실행하고 네트워크도 쓴다(README 1748행, SECURITY.md "Generated backtest code"). 사칭 토큰 사기 경고(README 53행).

### 1-3 Kronos (shiyu-coder) — 금융 봉(시가·고가·저가·종가·거래량) 전용 예측 AI 모델
- 무엇: 과거 봉을 넣으면 다음 봉들을 확률적으로 예측하는 트랜스포머 모델. 45개 이상 거래소 자료로 학습(README 서문). 모델 mini 4.1M·small 24.7M·base 102.3M 공개, large 499.2M 비공개(README Model Zoo). 논문 arXiv 2508.02739, AAAI 2026 채택(README News 2025.11.10).
- 판: 릴리스 없음, 커밋 76, 스타 44.0k, 이슈 217(페이지 표기), 마지막 커밋 2026-04-13(67b630e, 커밋 페이지). MIT(README License 절).
- 주문·키: **없음.** 증권사 연결 없음, LLM API 키 없음. 모델 가중치를 Hugging Face(NeoQuasar)에서 한 번 내려받는다. safetensors 형식(requirements.txt, model/kronos.py 4·13·180행 PyTorchModelHubMixin).
- 무게: PyTorch 2.0 이상 필요(requirements.txt). 예측은 GPU가 없으면 CPU로 자동 전환(model/kronos.py 494-501행). GPU 전제는 추가 학습(torchrun)과 대량 배치 예측뿐(README).
- 주의: 추가 학습 예시는 중국 A주(Qlib)이고 "실전용이 아닌 시연"이라고 스스로 적는다(README Finetuning 면책). 예측 신호만으로는 순수 알파가 아니고 비중 최적화·위험 중립화가 더 필요하다고 적는다(README "From Demo to Production"). 성능 수치는 논문 주장 → 가설.

### 1-4 skfolio — scikit-learn 기반 포트폴리오 비중 최적화·위험 측정 라이브러리
- 무엇: 평균-위험·위험 예산·최대 분산·HRP 등 비중 계산, Black-Litterman·요인 모형, 공분산 추정, CVaR·CDaR·최대 낙폭 등 위험 척도, walk-forward·CPCV 교차검증(README Available models).
- 판: v1.12.2(pyproject.toml 7행), BSD-3, 스타 2.6k·커밋 560(페이지 표기). Skfolio Labs가 기업 지원.
- 주문·키·LLM: **없음.** 계산 라이브러리. 의존성 numpy·scipy·pandas·cvxpy-base·clarabel·scikit-learn·plotly(pyproject.toml 56-64행). 예제 자료는 패키지에 들어 있고, 일부 큰 예제 자료만 github.com/skfolio/skfolio-datasets에서 내려받는다(src/skfolio/datasets/_base.py 118-165행).
- 주의: README 스스로 "평균-분산 최적화는 입력에 매우 민감하고 표본 밖 성적이 나쁘며, 1/N 같은 단순 배분이 표본 밖에서 더 나은 경우가 많다"고 적는다(README Key Concepts).

## 7. 이 결론을 바꿀 조건

- TradingAgents: 다중 LLM 토론이 우리 통합 점검·카드보다 낫다는 사전 등록 비교 결과(키움 가격으로 채점)가 나오면 → K3로 비교 시험을 제안.

- skfolio: 동적 레버리지 상한(alert_policy.json 580-598행)을 포트폴리오 단위 자료로 시험할 수 있게 되고 사장이 다시 열기로 정하면, 직접 코드와 skfolio 중 무엇이 더 단순·검증 가능한지 그때 비교.

**믿을 만한지 먼저 잰다 (사전 등록)**
- 방법: 2016-01부터 겹치지 않는 20거래일 구간(약 136개)마다, 그 직전 1,260거래일만으로 R2와 같은 방법으로 95% VaR·CVaR를 구하고, 다음 20거래일 실제 손익과 비교한다(지금 비중 고정).
- 두 판으로 잰다: (가) 전체(대리 포함) (나) 실제 자료만 — 그 구간에 실제 이력이 없는 종목의 비중은 현금으로 돌린다. 대리 종목은 기준과 결과가 둘 다 대리라 (가)만으로는 대리가 꼬리를 덜 잡는지 못 본다.
- VaR 보정: 손실선을 넘은 횟수가 5%와 맞는지 Kupiec 비율 검정 p ≥ 0.05(136구간이면 3~12회 = 맞음).
- CVaR 보정: Acerbi–Székely Z2 검정(각 구간의 예측 분포에서 모의 1만 번으로 임계값, 5% 유의). 넘은 구간의 실제 평균 손실 ÷ 예측 CVaR 비율도 함께 적는다(1보다 크면 꼬리를 덜 잡음).
- 판정: (가)·(나) 모두에서 두 검정을 통과하면 "보정됨". 아니면 위험 지도 머리에 어느 것이 안 맞는지(손실이 더 잦음/드묾, 꼬리를 덜 잡음) 그대로 표시한다.
- 이 판정은 위험 지도를 계속 볼지에만 쓴다. 한도·관문에는 쓰지 않는다.

**보는 방법 (1단계)**: 사장이 사장실에서 "위험 지도"라고 하면 그 자리에서 계산해 글자 그림 1장과 표 1개로 답한다. 정기 자동(2단계)은 1단계를 2~3번 써 본 뒤 따로 묻는다.

**하지 않는 것**: 한도·상한·노출 띠 바꾸기(K3), 줄이기·늘리기 추천, 카드·코어 입력.

**고정 설정**
- 모델: NeoQuasar/Kronos-small @901c26c1 + NeoQuasar/Kronos-Tokenizer-base @0e011738, 코드 shiyu-coder/Kronos @67b630e. CPU.

**비교 기준** (모두 시작점 직전 252거래일 실거래 일간 로그 수익률로; 252일이 안 되면 120일 이상 있는 만큼 쓰고, 120일 미만이면 시작점 제외 — Kronos와 같은 시작점만 비교)
- B1 랜덤워크: 평균 0, 표준편차 = 일간 표준편차 × √20인 정규분포.
- B2 추세 랜덤워크: B1에 평균 = 일간 평균 × 20을 넣은 정규분포.
- B3 과거 분포: 같은 252일 안의 겹치는 20거래일 수익률 표본.

**지표와 판정**
- CRPS 계산: B1·B2는 정규분포 공식, Kronos·B3는 표본 수 보정 CRPS(fair CRPS — 표본이 적을 때 생기는 불리함을 없앰).
- P1(주 지표) CRPS 점수 = 1 − (Kronos CRPS 전체 합 ÷ 가장 좋은 기준의 CRPS 전체 합). 기준 중 합이 가장 작은 것을 "가장 좋은 기준"으로 한다.
- 신뢰구간: 시작점이 5거래일 간격이고 예측은 20거래일이라 이웃 시작점 4개가 겹친다(1차 63개 ≈ 독립 구간 16개). 그래서 연속된 시작점 4개를 한 덩어리로(같은 시작점의 10종목은 함께) 뽑는 이동 블록 부트스트랩 1만 번으로 95% 구간을 구하고, 실효 표본 수를 함께 적는다.
- 통과 기준: P1 > 0 그리고 그 95% 하한 > 0. P2 80% 예측 구간 포함률의 95% 블록 부트스트랩 구간이 80%를 품는다.
- P3 방향(오름·내림) 적중률은 참고만, 판정에 쓰지 않는다.
- 1차 판정: P1·P2 모두 통과 = 통과. 하나라도 못 하면 종료하고 설정을 바꿔 다시 재지 않는다(바꿔 재면 사후 맞춤).
- 2차: 같은 격자에서 2026-10-30 이후 시작점만, 같은 코드·가중치·설정으로.
  - 2027-01-16 중간 보기(시작점 약 6개 ≈ 독립 1~2구간, 판정 없음, 보고만).
  - 2027-04-10 2차 판정(20거래일 뒤 종가가 2027-04-09 이전에 있는 시작점 전부): P1 > 0이면 유지, 아니면 종료. 표본이 작아 "방향 확인"이지 증명은 아니라고 적는다.
  - 실행: 날짜가 정해진 일이라 관제판 기다리는 일로 올린다(사장 확인 뒤). flow-attn 판정일(01-16·04-10)과 같다.

**통과해도**
- 할 수 있는 것: 카드·현황판 옆에 "참고 예측 구간"을 붙일지 따로 묻는다(B종류).
