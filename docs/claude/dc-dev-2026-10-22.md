## 2. Q1 절차 — Cowork 병합
1. 읽기: workspace/outputs/dev-runs/LATEST.json과 dev-runs/<id>/result.json. 둘 다 status READY_TO_MERGE, class general일 때만 진행.
2. 실행: Desktop Commander(PowerShell, 작업 폴더 = 저장소 메인 체크아웃) `powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\dev-merge.ps1 <id>`. -ApproveAuthority를 붙이지 않는다.
3. 결과: 출력 첫 줄과 종료 코드를 기록(dev-runs/_merge/<시각>-<id>/). 0 → git log 첫 줄 확인 후 사장에게 "병합 <id> <커밋>" 한 줄. 2 → 멈춘 이유를 사장에게, 다시 시도하지 않음(새 id로 다시 쓰거나 중단은 사장 결정). 3 → 권한 승격 — 사장 결정 요청.
4. 하지 않음: NEEDS_APPROVAL·FAIL·BLOCKED·STOP_* 병합, 실패 뒤 재시도 반복, 메인 체크아웃의 다른 파일 정리.

## 3. Q2 절차 — 수동 경로 실행 (사장 승인 뒤)
1. 사장 승인 문구(예 "결정 <id>: 승인")가 이 대화에 있는지 확인. 없으면 멈춘다.
2. Builder: Cowork가 docs/claude/<id>-builder-prompt.md를 쓰고, Desktop Commander로 저장소에서 `claude -p --worktree <id> --model <opus|sonnet> --permission-mode acceptEdits --tools "Read,Edit,Write,Grep,Glob,Bash,PowerShell" --strict-mcp-config` 에 지시문을 표준입력으로 준다. 결과는 worktree 브랜치 커밋 + 보고 파일.
3. Judge: 별도 프로세스 `claude -p --model opus --effort xhigh --tools "Read,Grep,Glob"`(편집 도구 없음)를 worktree에서 실행. 줄 것은 지시문의 Judge 확인 항목·diff·테스트 출력 경로뿐, Cowork의 결론은 주지 않는다. 보고는 docs/claude/<id>-judge-report.md(Cowork가 출력에서 옮김).
4. 병합: Judge PASS + 사장 결정 뒤 기존 병합 스크립트 방식(docs/claude/*-merge-*.ps1, ff-only)으로 Cowork가 실행. FAIL이면 같은 Builder 지시로 최소 수정 1회(헌법·지침 7절), 그래도 FAIL이면 사장에게.
5. CLI 플래그는 PC의 claude 2.1.305 기준 — 첫 실행에서 `claude --help`로 확인(확인 필요).
