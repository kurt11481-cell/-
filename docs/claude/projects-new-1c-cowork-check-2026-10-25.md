# 사장이 할 일 (한 번에 한 단계)
1. Cowork 새 대화를 연다(기존 대화도 가능).
2. 아래 "붙여 넣을 글" 전체를 Cowork에 붙여 넣고 보낸다.
3. Cowork의 답(보고표)을 사장실 대화에 그대로 붙여 넣는다. 사장실이 ①-c 재시험을 마무리한다.
4. (선택, 별도) 표본 (c)(d)(e)를 만들려면 문서 맨 아래 "사장이 할 일 — 표본"을 본다. 안 해도 된다. 안 하면 그 세 항목은 계속 미검증이고 K3 병합 뒤 8절 ④에서 확인한다.

# 붙여 넣을 글
```
읽기 전용 확인 1건만 한다. 파일·메시지·설정을 쓰거나 바꾸지 않는다.
금지: 쓰기 전부(파일, 채팅 메시지, 일지, 대조 원장, 정책, 설정), 승인류(apply, '확인 <코드>', 켜, dev-merge, -ApproveAuthority, 예약 작업 변경, 기억 쓰기), 키움 도구 호출(조회 포함), auto_core.py 실행, 인증·로그인. 이 중 하나라도 필요해지면 멈추고 "필요: <무엇>"만 쓴다.

할 일: "투자_V2 사장실" 프로젝트 채팅의 메시지를 id로 읽을 수 있는지 확인하고, 읽은 결과에 어떤 필드가 있는지 그대로 보고한다.

1) 읽기 수단 확인
- 사장실(Projects) 채팅 메시지를 읽는 도구가 이 대화에 있는지 쓴다. 있으면 도구 이름, 없으면 "읽을 수단 없음"이라고 쓰고 여기서 멈춘다(추측으로 대신하지 않는다).

2) 읽을 메시지 id (읽기만)
- cmsg_0137MRzn9nuDvvQmVxm6WeX9JJkEM9xNbfyuU4oumxJ7UM  (사장 직접 입력)
- cmsg_0137MRzn9nuDvvQmVxm6WeX9PYSdWDDbeUahrRJ8x4PBSL  (사장 직접 입력)
- cmsg_0137MRzn9nuDvvQmVxm6WeX9JzJn64991qwDeNaTyfneX2  (사장 직접 입력)
- cmsg_0137MRzn9nuDvvQmVxm6WeX9WfgLvsuaX4iPEWZGMUZ8eM  (코디네이터 작성)

3) 보고 (표 1개, 값은 읽은 그대로 — 지어내지 않는다)
| id(끝 6자) | 읽힘? | 작성자 필드와 값 | 작성자 계정 id 필드 유무와 값(앞 12자만) | trust 또는 role 필드 유무와 값 | 편집 표시 필드 유무와 값 | 출처(사람 직접 입력/트리거/예약 등) 필드 유무와 값 | 시각 필드 | 본문 전체 반환 여부 |
- 필드가 없으면 "없음"이라고 쓴다. 필드 이름도 읽은 그대로 쓴다.
- 읽기 결과에 있는 모든 필드 이름 목록도 한 줄로 쓴다.
- 본문이 12절 인용과 같은지는 판정하지 말고 본문 첫 20자만 쓴다.

4) 마지막에 3줄로: ① 읽을 수 있었는가 ② 작성자가 사장 계정인지 코디네이터인지 구별되는가 ③ 사람 직접 입력과 트리거·예약·릴레이 입력을 구별하는 필드가 있는가(없으면 "없음, 확인 못 함").
```

# 통과 판정 (사장실이 한다, Cowork가 하지 않는다)
- ⓪ 읽을 수 있음. ① 사장 3건은 같은 계정 id, 코디네이터는 다른 값. ② trust/role 또는 출처 필드가 있고 사람 직접 입력과 relay를 구별. ③ 편집 표시 필드가 있음. ④ 본문 전체 반환.
- 하나라도 없으면 실패. 실패하면 정의대로 K3 ①을 멈추고 (가)로 다시 묻는다. (c)(d)(e) 표본이 없으면 계속 미검증 = 실패 취급이다.
- 바뀔 증거: Cowork의 읽기 결과에 trust/role·출처·편집 필드가 있으면 ②③ 통과로 바뀐다.

# 사장이 할 일 — 표본 (선택, 별도)
이 스레드는 메시지를 만들 수 없다(쓰기가 되어 "쓰기 없음"과 충돌). 표본이 필요하면 사장이 직접 하고, 한 번에 하나씩, 만든 뒤 사장실에 "표본 (c)/(d)/(e) 만들었음"만 알린다.
- (e) 편집된 메시지: 사장실 채팅에 "표본e 원본"이라고 보낸 뒤, 앱에서 그 메시지를 "표본e 수정본"으로 직접 수정한다(수정 기능이 있을 때만; 없으면 "수정 기능 없음"만 알린다).
- (d) 선택 카드 응답: 사장실이 일반 선택 카드를 하나 내면(정책·권한과 무관한 문구) 사장이 누른다. 사장실에 "표본 d 카드 부탁"이라고 말하면 된다.
- (c) 트리거·send_later 턴: 사장실에 "표본 c 알림 예약 부탁"이라고 말하면 사장실이 승인류가 아닌 무해한 알림 예약을 요청한다. 단, 예약 작업 만들기는 승인류라 지금은 사장이 이 줄을 직접 허락하는 한 줄을 입력해야 한다. 허락하지 않으면 (c)는 미검증으로 둔다.
- 셋 다 안 해도 K3 지시문 작성에는 영향이 없고, 그 경우 해당 거부 규칙은 지시문이 코드·문구로 막고 병합 뒤 8절 ④에서 확인한다.
