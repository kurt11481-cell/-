# R-REC1 EV4 사건 시작 1회 — 사전 등록

## 0. 요약

- **문제.** 운영 R-REC1은 EV4(계좌 총액 ≤ V6 1차 선 또는 ≤ S7 HWM × 0.9)가 켜진 세션마다 그 세션을 사건일로 넣고(`auto_core_decide.py` 746~747·1084~1090행, 리플레이 `auto_core_replay.py` 215·262~263행), 기준 사건은 60세션 창 안 가장 최근 사건이다(`auto_core_rules.py` 894~895·907행 `event = events[-1]`). 계좌가 선 아래인 동안 사건일이 매일 새로 잡혀 RG1(사건 뒤 2세션)·RG3(사건 종가 위 2종가)를 채울 수 없다. 그래서 관문은 계좌가 선 위로 돌아온 뒤에야 열린다(buylow 검토 2절: 지금 +14.9%, hwm-fix 뒤 +20.4%).
- **정의가 두 곳에서 다르다.** 규칙 문서는 EV4를 "계좌 점검선 L1(고점 대비 −10%) **열림**(기존 S5 R4)"으로(recovery-gate 26행), 첫 관문 모듈 지시문은 EV2 "참인 날마다 이벤트일"과 달리 EV4를 "입력 열림일"로 적었다(r-rec1-gate-module-builder-prompt 33행). 정책 점검선은 "선마다 낙폭당 1회, 새 HWM에서 재무장"이다(`alert_policy.json` 829~831행). 반면 승인된 T2 지시문은 EV4를 상태("총자산 ≤ 25,626.55 또는 ≤ S7 hwm × 0.9", redesign-t2-builder-prompt 448행)로 정의했고, 운영은 그대로 구현됐다. 그 뒤 r2 R2-3이 평가 세션 자신을 더했다(Judge2 F-3 PASS, redesign-t2-judge2-report 50행). 승인된 정의를 바꾸는 것이라 권한·한도 경로다.
- **질문.** EV4를 "사건 시작"으로만 세면, 현행(매일)보다 결과가 낫고, 꼬리가 기준 이하로 나빠지지 않는가.
- **판정 변형 2개(E1·E2), 진단 1개(E3). R-REC1 코드(`rrec1`)는 그대로 부르고 `ev4_sessions` 입력만 바꾼다**(rrec1 안에서 EV4를 쓰는 곳은 894행 하나).
- **지금 당장 관문이 열린다는 뜻은 아니다.** 10/14·10/15·10/16은 EV2도 매일 켜졌다(LATEST_DECISION.json, 세션 2026-10-16, shock.events). EV2 상태 읽기는 승인 설계라 이 사전 등록이 바꾸지 않는다. 또 S7 L2 신규 매수 멈춤이 관문과 별도로 매수를 막고(`auto_core_tickets.py` 240~241행, 같은 기록에서 총액 23,695.43 < 0.8 × 30,255.36), 해제는 "일지 검토 완료 그리고 사용자 확인"이다(`alert_policy.json` 834행). 이 변경이 없애는 것은 "계좌가 선 아래인 동안 끝없이 다시 잡히는 사건"뿐이다.

## 3. 대리 계좌 (EV4를 과거에 재현하는 방법)

- 운영 EV4 = `rules.ev4_open(총액, S7 hwm)`(724~731행). 과거 계좌는 없으므로 대리 계좌를 만든다.
- A_0 = 28,473.94(`hwm_initial_usd`, alert_policy 812행)를 자료 첫 세션 종가에 둔다. A_t = A_{t−1} × (1 + L × r_t), r_t = 벤치마크 일간 종가 수익률(P1 SOX 원값, P2 SOXX 조정값, SOXX 전체 날짜로 한 번 만듦). 매일 재조정, 현금 부분 수익·비용 0.
- total_t = `Decimal(f"{A_t:.2f}")`. HWM_t = total_t > HWM_{t−1}일 때만 갱신(같으면 갱신·재무장 없음, portfolio_exposure 717~719행), HWM_0 = total_0. 재설정 없음(`hwm_update: new_closing_equity_high_only`).
- EV4_t = `rules.ev4_open(total_t, HWM_t)`(운영 함수 그대로, Decimal). V6 1차 선 25,626.55는 28,473.94 × 0.9 = 25,626.546의 반올림이라 HWM = 28,473.94일 때만 $0.004 차이가 난다.
- **L = 1.55(주)**: 정책 노출 목표(alert_policy 684행 `target_exposure`). 참고로 최신 S7 E는 1.2847(LATEST_DECISION, 세션 2026-10-16). 민감도 L = 1.0·2.0.
- 자료 첫 날 HWM(P1 1994-05-04, P2 2010-01-04)은 임의다. 평가 시작 전 앵커는 빼지만 첫 낙폭의 HWM은 이 시작값에 기댄다(한계).
- 한계: 대리 계좌는 벤치마크 하나만 담는다. 실제 계좌(MVLL·NBIS·SOXL·현금, 매매·입출금)와 다르고, EV4가 벤치마크 하락(EV2)과 겹치는 정도가 실제보다 클 수 있다.

## 4. 변형 (판정 대상 E1·E2, E3는 진단)

세션 t의 판정에는 t 이하 세션만 담은 목록을 넘긴다(미래 정보 없음). 선 분수는 Decimal(0.9, 0.8, …, 0.1), 비교는 반올림 없음.

| 변형 | `ev4_sessions` | 근거 |
|---|---|---|
| V0 | EV4_k가 참인 모든 세션 k | 운영 decide 746~747·1089~1090, replay 262~263 |
| E1 | 낙폭마다(HWM 갱신 사이) total_k ≤ HWM_k × 0.9가 처음 참인 세션 1개 | 2-1 표 |
| E2 | EV4_k가 참이고, k가 자료 첫 세션이거나 EV4_{k−1}이 거짓인 세션 | 2-1 표 |
| E3 | 선 j 각각에 대해 낙폭마다 total_k ≤ HWM_k × 분수_j가 처음 참인 세션. 하루에 여러 선 = 사건일 1개. V6 항은 쓰지 않는다 | alert_policy 825~831 |

- "V0 = 운영"은 기록이 빠진 날이 없을 때만 성립한다. 운영은 빠진 날을 다시 구하거나 이웃 3% 규칙으로 열림 쪽으로 판정한다(decide 217~280행 backfill) — 리플레이는 모든 세션을 계산하므로 해당 없음.
- **채택되면 바뀔 곳(지금은 아무것도 안 바꿈):** decide의 `ev4_all` 조립, `auto_core_replay.py` 215~263행, t2rc-oracle 계산기. Judge 확인 필요 항목: (1) E3를 S7 breach_date로 구현하면 S7 자산 기준(현금 흐름 HWM 조정 715행, hwm-fix 하한 739~742행, HELD/UNVERIFIED 상태)과 EV4의 decide 총액(1085행)이 같은지, (2) S7이 판정 보류일 때 fail-closed(매수 막힘)가 유지되는지, (3) E1·E2가 직전 세션 EV4 기록이 없을 때 그 세션을 시작일로 보는지(매수 쪽 보수).

## 5. 호출 방식

- r3 사전 등록 3-1 그대로: 자료마다 `build_series` 한 번, 세션 t 판정에 모든 리스트 키를 t까지 마지막 130세션만 잘라 넘김. `rrec1(benchmark, candidate, evaluation_session=t, ev3_user_dates=[], thesis_damage=[], ev4_sessions=<변형 목록>, candidate_symbol, research_sessions=None, rg2_series)`, `card_accepted_on` 기본값.
  - P1: r3와 같게 benchmark = SOX, candidate = None(후보 = 벤치마크 자신이라 status가 같음).
  - P2: benchmark = SOXX, candidate = 후보, rg2_series = `rg2_benchmark(섹터)` 계열(섹터 문자열은 r3 3-1 고정값: MU "B1 메모리", LITE "A3 광부품", DELL "AI 서버", PWR "A1 전력(그리드 시공)", BE "A1 전력(온사이트)"). EV4 목록은 SOXX 대리 계좌에서 한 번 만들어 모든 후보에 같게 넘긴다. 그 후보의 공통 날짜에 없는 EV4 사건일은 다음 공통 날짜로 옮긴다(사건이 사라지지 않게, 막는 쪽).
- 매수 허용 = `status == "ok"`(tickets 268~279행, ev-rg1-hyper 뒤에도 같음).

## 6. 앵커와 비교 팔

- **앵커 a = E2 사건일(EV4 꺼짐 → 켜짐)**, 모든 변형 공통. E1·E3의 L1 사건일을 모두 포함한다(E1 ⊆ E2). 종류(낙폭 첫 닿음 / 다시 내려감)를 나눠 보고한다.
- **S7 멈춤 모형.** 세션 k가 속한 HWM 구간(직전 HWM 갱신 세션 h(k) 다음부터 k까지)에서 total ≤ HWM × 0.8이 처음 참인 세션을 ℓ(k)라 한다(없으면 ∞). 멈춤(k) = ℓ(k) ≤ k. S7 판정은 장 마감 뒤라(alert_policy 835행) ℓ 당일 판정의 다음 날 체결도 막힌다.
  - 가정(공개): 운영에서 멈춤은 열린 L2 이상 사건이 검토·사용자 확인될 때까지 이어지고 새 HWM으로 풀리지 않는다(portfolio_exposure 1378~1386행, alert_policy 834행). 모형은 "그 HWM 구간 끝(새 HWM)까지 멈춤"으로 둔다 — 사용자가 빨리 검토하면 실제보다 엄격하고, 검토하지 않으면 실제보다 느슨하다.
- **주 판정 앵커 = 멈춤(a)가 거짓인 앵커**(a 당일에 L2에 닿은 앵커도 뺀다). 나머지는 진단(D5).
- 앵커는 평가 시작 뒤이고 r3 5절의 왼쪽 검열(창 [a−59, a] 모든 세션에 벤치마크 σ60, P2는 후보 σ60도)을 통과해야 한다. P2는 SOXX·후보(·GRID) 공통 날짜만 쓰고, 앵커가 공통 날짜에 없으면 그 후보에서 뺀다(개수 보고).
- 변형 V의 매수: u_V = a 이후(a 포함) 처음 허용인 세션, 체결 f_V = u_V + 1, 체결가 P = 종가 × 1.001(10bp). 매수 대상 = P1 SOX, P2 그 후보.
  - **매수 성립 조건:** 멈춤(u_V)이 거짓이고 f_V ≤ a + 120. 아니면 "못 삼"(모든 변형·X1′·X_D에 같게). 멈춤을 무시한 읽기는 D5.
- 기준 팔: **X1′** = f = a + 1(같은 멈춤 규칙). N = 매수 안 함 — 표에만. 진단 팔 X_D = 앵커마다 그 변형과 같은 지연으로 매수(같은 멈춤 규칙, D8).
- 지표 두 종류:
  - **체결 기준(r3 정의):** R60 = close_{f+60} / P − 1, MAE60 = min(low_{f+1..f+60}) / P − 1. **판정 쌍 = 그 변형과 X1′ 모두 매수가 성립하고 f+60이 자료 안인 주 판정 앵커**(r3 6절 판정 쌍과 같은 방식). 변형이 못 산 앵커는 X1′도 빼므로 X1′만 깊은 하락을 떠안지 않는다(대신 변형에 불리한 쪽으로 기울 수 있음 — 막는 방향). 빠진 앵커 수와 그 앵커의 X1′ R60·MAE60은 D2에 보인다.
  - **앵커 기준(현행이 늦게 사거나 못 사는 비용):** 주 판정 앵커마다 Q120 = close_{a+120} / P − 1 (매수 성립), 아니면 0(현금). f_V = a+120이면 −0.1%(비용)라 0과 작은 비대칭이 있다. a+120이 자료 끝을 넘으면 그 앵커를 뺀다.
- 한계: 깊은 하락에서는 앵커가 몰리고 창이 겹친다(독립 표본 아님).

## 7. 채택 기준 (계산 전 고정)

각 변형 E ∈ {E1, E2}를 6절의 주 판정 앵커로 계산한다(d는 Q120 가능 앵커, b·꼬리는 그 변형의 판정 쌍). 중앙값 = `statistics.median`, 하위 10% = `numpy.percentile(x, 10)` 선형 보간, 반올림 전 값으로 비교.

| # | 기준 | 출처 |
|---|---|---|
| d | median Q120(E) − median Q120(V0) > 0 (현행이 늦게 사거나 못 사서 잃는 몫이 실제로 있다) | r3 C안의 방향을 앵커 기준으로 옮김 |
| b | median R60(E) − median R60(X1′) ≥ −3.0%p (체결 기준) | 10/9·r3 그대로 |
| 꼬리 | **사용자 선택 Q1(아래), 체결 기준 MAE60** | — |

- **Q1 꼬리 기준(고정 전 사용자 선택):**
  - **A (권장): c₀** — P10 MAE60(E) − P10 MAE60(X1′) ≥ 0. "고친 관문으로 산 매수의 꼬리가 충격 다음 날 매수보다 나쁘지 않다."
  - B: r3 그대로 — median MAE60 차(a) ≥ +2.0%p 또는 P10 MAE60 차(c) ≥ +2.0%p.
- **변형 E의 채택 후보 조건(모두):**
  1. P1 주 판정 앵커에서 d ∧ b ∧ 꼬리.
  2. P1 반분(a ≤ 2010-12-31 · a ≥ 2011-01-01) 각각에서 d ∧ b, 그리고 꼬리 차이 값(A: c₀ 값, B: 1에서 충족한 a 또는 c의 차이)이 ≥ 0.
  3. P2 합동(후보 5종, 같은 SOXX 앵커를 후보 수만큼 다시 셈)에서 d ∧ b, 그리고 꼬리 차이 값 ≥ 0.
  4. 민감도 L = 1.0·2.0 각각의 P1에서 d ∧ 꼬리(막는 쪽으로만 작동).
- 체결 기준 쌍 또는 앵커가 15개 미만이면 "표본 부족": P1이면 판정 보류(= NO_CHANGE), 반분·P2·민감도면 미충족.
- 둘 다 통과하면 E1(단순화, 규칙 문서 "L1 열림"과 같음)을 고른다.
- 통과 변형이 없으면 **NO_CHANGE**: 현행 유지, 결과 기록·알림만(사용자 질문 없음).
- 통과해도 바로 바뀌지 않는다: 독립 Judge(Opus, 별도 세션, 4절 확인 필요 항목 포함) → 사용자 승인 → 수동 경로 Builder → Judge → 사용자 병합. 병합하면 t2-rc 독립 대조 C1이 다시 0/10부터 센다(ev-rg1-hyper 때와 같음). 관문은 계속 매수를 막거나 늦추기만 하고 매도·예산·노출 상한에 영향 없다.
- **기준 이동 위험(정직하게 적음):**
  1. r3 결과를 이미 봤다: EV4 없는 관문(r3 V0)은 P1(SOX 1994~2010)에서 a +0.97·c +1.14%p로 +2.0%p를 넘지 못했다(r3 결과 1절). E1~E3는 EV4가 드물어져 r3 V0와 비슷하게 움직일 것이므로 **Q1 B를 고르면 결과가 거의 NO_CHANGE로 정해져 있다.**
  2. A는 r3보다 느슨하다. 이유: 이 질문은 "관문 전체가 충격 매수보다 낫나"(r3 미달, 사용자는 규칙 후보 D로 유지)가 아니라 "현행의 매일 EV4가 추가로 막는 것이 값어치가 있나"이다. B를 쓰면 검증되지 않은 더 엄격한 현행이 기본으로 남는다.
  3. r3와 다른 점: P1이 처음 보는 1994~2010에서 1994~2026으로 넓어졌다(2011~ 앵커는 2020-12~2026뿐이고, r3 P2·buylow 검토에서 본 구간). r3의 c′(변형 꼬리 ≥ 현행 꼬리)는 기준에서 빠졌다 — 현행보다 일찍 사므로 꼬리가 나빠질 수 있고, 그 크기는 D6에 판정 표와 나란히 보이며 채택은 그 표를 본 사용자 승인으로 정한다. 반분·P2 꼬리 조건은 r3의 "> 0" 대신 "≥ 0"(A의 동등 기준과 맞춤).
  4. d는 "현행이 앵커 뒤 120세션 안에 못 사는" 경우가 많으면 사실상 "E로 산 결과의 중앙값 > 현행(≈ 현금)"이 된다. 앵커 뒤 시장이 중앙값으로 하락이면 d는 실패한다. V0가 창 안에서 못 산 비율은 판정 표에 같이 보인다. 관문 판정이 "같은 기간 그냥 기다리기"보다 나은지(X_D, D8)는 판정에 넣지 않았다 — 승인 단계의 보류 근거로만 쓴다(11절).
  5. A를 고르면 결과 문서 첫 줄에 이 문단을 적는다.

## 8. 진단 (판정 없음)

- D1 막힘 비율: 평가 세션 중 status ≠ "ok" 비율, 변형별(P1·민감도·P2 후보별). EV4 상태 비율.
