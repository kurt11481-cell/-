# 주간 팀장회의 v1.5 단순화 — 설계안 (2026-11-13)

## 0. 결론

- **세 가지를 바꾼다.** ① 결정 답하는 길: 직접 입력 양식(`결정 ceo-<날짜>: D1 …`) → 사장실 결정 카드(버튼). ② 비서와 겹치는 점검 빼기: 관제판 R4·R5·R6과 '예약 작업 출근부'·'통합점검 실행 상태' 전체 목록 → 주간은 이상 있을 때만 한 줄. ③ 비서 파일을 받은 결과로 읽기: 그 주 비서 제안(workspace/outputs/secretary/*.md)의 '멈춤 의심'·'계속 n일째'를 운영관리 받은 결과 1건으로.
- **남긴다.** 주간 추세(코어 정상 n/5·대조 일치 n/5), 팀별 받은 결과·팀장 확인·연계 검토, 감사실 절, 다음 주 일정, 매주 1줄 푸시, 보고 파일 덧붙이기.
- 바뀌지 않는 것: 일정(일 09:47)·모델(Sonnet 5.5)·폴더·권한 모드·쓰기 범위(보고 파일 + _pending 1개)·절대 금지 목록.
- **사장 손: 적용 승인 1번**(`예약 작업 변경 승인: 주간 팀장회의` 직접 입력 + PC 앱 승인 창). 일상 손 0 그대로.

## 4. 2단계 (적용 묶음 — 시스템 몫, 사장 결정 없음)

1. ceo.py v1.5 수정본 + ceo-weekly-meeting.txt v1.5(4)㉲ 한 줄, 3) sha256 두 값, 머리 버전) + 결과 모음 지시문 'D 줄 → 카드' 수정본을 scheduled-prompts/pending-ceo-weekly-v15/에 둔다(쓰기 전 사본 포함).
2. 시험: 보고 4회분(10/19~11/08) 연쇄 재실행으로 ①~④ 확인 + 지난 절 한 글자도 안 바뀜(덧붙이기만) + 형식 검증 OK. 독립 검토 1회.
3. 제안서 머리에 지금·바꿀 지시문 sha256, diff, 일정·모델·폴더·권한 모드 불변, 되돌리는 법(지금 판 ceo-weekly-meeting.txt a7b12735… · ceo.py b1f7cc0c… 로 지시문 교체)을 붙여 사장실에 승인 문구 2개(주간 팀장회의 · 사장실 결과 모음)를 한 번에 올린다.
- 크기: ceo.py 743행 압축 코드 수정 + 시험이라 별도 세션(지침 7절 '제안서·개발 지시문' 등급)에서 한다. 이 문서는 그 세션의 입력이다.

## 5. 확인 필요
