# 외부 주장 원장 → 판단 반영 전략 (제안, 2026-10-27)

**부딪히는 결정(첫 줄):** ① pvault: A(active-decisions.md:42 — 원장 경로 재사용, 통합 점검·비서가 보관함 직접 읽기 B는 하지 않음) ② ext-1027(active-decisions.md:43 — 원장 쓰기 주체 = Cowork 또는 사장실 회사PC 스레드) ③ t2-gate: REMOVE-v2(active-decisions.md:78 — "켜" 조건. 이 제안은 코어·비교 판정을 건드리지 않으므로 충돌 없음) ④ 팀장회의 v1.5 교체는 board-merge Q2 조건 충족 때만(active-decisions.md:90) — 그래서 주간 보고 변경(B안)은 지금 올리지 않고 사전 등록만 한다.

## 0. 결론

1. **원장은 이미 '보관만' 되는 것은 아니다.** 매일 06:40 통합 점검이 원장을 읽고 확인 조건이 온 항목을 채점해 "결과 제안"을 남긴다. 다만 **그 뒤 고리(사람 확정 → 카드 → 학습)가 끊겨 있어** 결과가 시스템에 돌아오지 않는다.
2. **원장을 매매 엔진(자동 코어)에 직접 넣지는 않는다(NO_CHANGE).** 코어가 받는 LLM 입력은 연구 기록 하나뿐이고, 그 안의 사실 칸은 회사 공식 출처만 받는다. 외부 주장이 지식으로 쓰이는 정상 경로는 "원장이 확인할 때를 알려 줌 → 점검이 공식 사실을 찾음 → 카드 트리거 → 코어"다. 이 경로는 이미 있다.
3. **추천 A(문서만, 코드·예약·정책 변경 0):** ⓐ 2주째 멈춘 확정 대기를 버튼 한 번으로 처리하는 주기 만들기 ⓑ 만료·R0 항목을 4절로 옮겨 원장을 가볍게 ⓒ 실제로 작동하지 않는 학습 규칙 8을 실제 있는 출처 기록(3절)으로 바꾸기 ⓓ 시장환경 항목에 SCN-27H1 트리거 번호(T1~T6)를 붙여 이미 있는 레짐 점검과 연결.
4. 출처별 적중률로 근거 강도를 가중하는 안은 **지금은 하지 않는다.** 판정이 끝난 결과가 출처당 최대 2건이라(3절 표) 원장 규칙 8의 "10건 미만이면 비율을 쓰지 않는다"에 걸린다. 근거 강도를 바꾸는 것이라 하게 되더라도 K3.

## 4. 사장 결정

- **A(추천) 문서 정리안:** S1(만료·R0만) + R1(+기본 처분) + R2 + R3 + P1. 원장 파일과 이 문서만 바뀜. 코드·예약·정책·카드·코어 변경 0. 승인 뒤 같은 스레드에서 원장 수정안(diff)을 먼저 보여 주고 버튼으로 한 번 더 수락받아 쓴다(원장 규칙 5).
- B: A + A1을 지금 따로 올림 — 팀장회의 v1.5 조건(active-decisions.md:90)과 부딪힘. 비추천.
- C: NO_CHANGE — 지금처럼 점검이 매일 제안만 반복.
- 무응답 기본 처분: C(NO_CHANGE).

A를 고르면 바로 이어서 할 것: ① 지금 확정 대기 3건(EXT-20261004-01 맞음 제안, 20261005-05 미정, 20261019-01 미정)과 만료 3건(20261002-02·03·04)을 버튼 카드로 올림.

## 5. 바뀔 조건
