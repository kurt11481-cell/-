보유 종목이 바뀌어도 점검 공백이 생기지 않게, 보유 목록을 매 실행 키움 잔고에서 읽고 모든 보유·관심 종목에 같은 대칭 공통 규칙을 적용한다. 승인돼 있던 위험 규칙(S7 노출 대역·종목 상한·고점 −30%·R-REC1)을 매일 점검 화면에 연결했다. 권한·쓰기 범위·주문 금지는 그대로다.

## 2. 공통 규칙 C (제안·D등급·미검증, 리플레이 검증은 나중)
| 매도 쪽(−) | 매수 쪽(+) |
|---|---|
| C1- 강세 과열: RSI14 ≥ 70 또는 종가 ≥ EMA20 + 2×ATR14 | C1+ 약세 과매도: RSI14 ≤ 30 또는 종가 ≤ EMA20 − 2×ATR14 |
| C2- 과열 뒤 밀림: 고가 ≥ EMA20 + 2.5 ATR, 종가 위치 ≤ 0.35, 거래량 ≥ 1.2배 | C2+ 과매도 뒤 반등: 저가 ≤ EMA20 − 2.5 ATR, 종가 위치 ≥ 0.65, 거래량 ≥ 1.2배 |
| C3- 추세선 이탈: EMA20 아래 2회 연속 | C3+ 추세 회복: EMA20 위 2회 연속 |
| C4- 가짜 돌파: 20일 종가 고점 위 마감 뒤 복귀 | C4+ 가짜 붕괴: 20일 종가 저점 아래 마감 뒤 회복 |
| C5- 신저가 이탈(2세션 유지) | C5+ 신고가 돌파(2세션 유지) |
| C6- 반등 실패 | C6+ 눌림 반등 |
| C7- 호재 뒤 하락 | C7+ 악재 뒤 상승 |
| C8- 급락 경보(검토) | C8+ 급등 경보(검토, 차익 실현 검토 개시) |

- C1·C2 띠는 t−1 세션 EMA20·ATR14 기준. 사건형(C2·C4·C6·C7)은 충족일 포함 5세션 동안 1개. 같은 종류(카드 별칭 포함)는 종목당 1개.
- 근거 집계·알림 기준은 기존과 같다: 공식 사실 1 또는 같은 종목 가격 단서 2 → 매도 검토/매수 근거 후보. 과열·과매도는 단독으로도 "근거 1/2" 경보.
- 매도 전용 상품(MVLL)의 + 쪽은 표시만("매수 불가 상품").
- 기준값 출처: 과열 뒤 밀림 정의는 옛 경보 엔진(alert_policy.json overheat_* 값: 2.5 ATR, 종가 위치 0.35, 거래량 1.2)을 다시 썼다. 나머지 수치는 이번에 정한 D등급 제안값이다.

## 3. 바뀌지 않은 것
- 주문·정정·취소 금지, 상태·정책 파일 수정 금지, 쓰기는 대시보드 저장소 한 곳(통합 점검)·메모 폴더(SAVE·월요일)뿐.
- 신호는 "근거 확인됨, 사용자 판단 필요"까지. 수량·가격 지시는 위원회를 거친 지시서에서만.
- HWM·1차 선은 V6 지시문 기준 유지(2026-10-03 사용자 결정 iii). S7 HWM은 참고 한 줄. 추적형 전환은 S7 2단계.
- 손절 참고선 S8·N9는 S7 2단계 전까지 표시 유지.

## 4. 독립 검토 반영(요지)
R-REC1 이벤트 조회 창 20 → 60세션(열린 이벤트가 창 밖으로 빠지는 fail-open 차단), ② 판정에 오늘 N ≥ 1.85 직접 적용(S7이 하루 늦는 문제), 보유 추가 행에 add 멈춤·종목 상한·R5 연결, 묶음 관심 절(MU·BE·DELL·AMD)만 있는 보유 종목도 판정, EV3 정규식·공식 테제 충격 경로, EV4 두 HWM 중 엄격한 쪽, 미등록 배수 급락 임계 10%, R5 기준일이 추가 매수로 다시 잡히지 않게, S7 폴더는 날짜 이름만, DRAM 배수·지수 ETF 제외, 뉴스·saveticker 대상 동적화, 반복 억제용 triggers 기록, C5·C6 문구, 합치기 모순 정리, python 상태 파일 읽기 예외 처리, 월요일 점검 빈·오래된 기록 대체.

## 5. 남은 일(이번 범위 밖)
1. 통합점검 대시보드 페이지(K1): 매수 요건 표 머리 "② E<1.9", "⑤ 알려진 이벤트"와 "S5 초안 상한 미적용" 문구가 낡았고, 새 필드(exposure·peakReviews·shock)를 화면에 그리지 않는다. 기록은 저장소에 남으므로 판정·알림에는 영향 없음.
2. S7 노출 검토 실행이 예약돼 있지 않다(수동 실행, 마지막 10/7 세션). 통합 점검은 오래되면 "S7 검토 오래됨"으로 막힘 쪽에 둔다 — 매일 갱신 경로는 별도 결정(K2 가능성).
3. SEC 피드 수집 명단(Windows 작업)에 새 보유 종목을 넣는 일 — 불일치는 매일 표시되고 WebSearch로 대신 확인한다.

## 6. 적용 방식 (2026-10-09 06:5x KST)
- 통합 점검 지시문 전체(약 80KB)는 예약 작업에 넣을 수 없었다(두 번 모두 승인 없이 거절, 64KB 안팎 크기 제한으로 추정 — 확인 필요. v3.11은 약 63KB로 적용됐었다).
- 사용자 선택 "규칙 파일 + 해시 고정": 예약 작업에는 짧은 지시문(v3.12-L, 약 4KB)만 넣었다. 실행할 때마다 규칙 파일의 sha256(CRLF→LF 정규화)을 확인하고, 다르거나 못 읽으면 판정 없이 "통합 점검 중단" 알림만 보낸다. 절대 금지 목록은 짧은 지시문에도 두어 규칙 파일보다 우선한다.
- 규칙 파일을 고치려면 새 해시를 넣은 짧은 지시문도 함께 승인받아 바꾼다(파일만 바꾸면 다음 실행이 멈추고 알린다).
- 적용 확인: 예약 작업에 저장된 지시문이 loader 파일과 일치(끝 줄바꿈 제외), 다음 실행 2026-10-10 06:40 KST. 월요일 점검 v2.1·SAVE 메모 v2.1은 정확히 일치.
