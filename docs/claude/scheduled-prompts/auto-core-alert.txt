5) 알림(PushNotification 한 번, 한 줄): 아래 해당 항목을 " / "로 이어 "자동 운영 코어 <TODAY의 MM/DD>: …"로 보낸다. 해당 없으면 보내지 않는다.
 ⓪ TODAY 줄이 MISMATCH → "날짜 계산 불일치 — 확인 필요"(그 뒤 항목도 함께)
 ① T1 NO_FILE 또는 STALE → "daily 결과 없음(미실행·진행 중) — 확인 필요"
 ② T1 STATUS가 OK가 아님 → "daily <STATUS> — <T1 REASONS 첫 항목> (비교 <STREAK>/3)"
 ③ T1 APPLIED가 True이고 T1 WARNINGS가 있음 → "daily 기록됨, 경고 — <첫 항목>"
 ④ T1 NEXT가 있음 → 그 문구
 ⑤ D NO_FILE 또는 D STALE → "판정(decide) 결과 없음(미실행·진행 중) — 확인 필요"
 ⑥ D FRESH이고 STATUS가 FAIL → "판정 FAIL — <D REASONS 첫 항목>"
 ⑦ D PUSH 줄(decide가 정한 알림 — 비교 모드에서는 예외만 나온다) → 그 문구들(최대 3개, 나머지는 "외 N건")
 ⑧ D RERUN 줄 → "같은 날 재실행 결과 다름 — Cowork 확인"
 ⑨ D RESEARCH가 OK가 아니고 NO_NEW_SESSION이 True가 아님 → "연구 기록 <상태>(<사유>) — 오늘 매수 막힘"
 ⑩ D NEXT_USER가 있음 → 그 문구(기록 모드의 "주문표 N건 — 저녁 키움 입력")
 ⑪ D NEXT_COWORK가 있음 → "<그 문구> — Cowork 확인"
 ⑫ R FRESH이고 VERDICT가 MISMATCH 또는 ERROR → "독립 대조 <VERDICT>(<REASON>, C1 <C1>·누락 <MISSING>·추가 <EXTRA>·주문표 누락 <LEAKS>) — Cowork 확인". R NO_FILE·STALE이고 D FRESH이면 → "독립 대조 결과 없음 — 확인 필요". VERDICT가 MATCH·NOT_CHECKED이면 알리지 않는다
 ⑬ D HOLD 줄(기록 모드에서 그 방향이 아직 확인되지 않았고 그 주문표에 오늘 독립 대조 일치 기록이 없음 — 새 세션 없음 날 앞 기록에서 넘어온 주문표(dashboard.orders)도 같은 검사, 독립 대조 결과는 같은 decision(generated_at)을 본 것만 씀) → "주문표 확인 대기(<방향>: <종목>) — 입력 금지". 그 종목의 ⑦ 주문표 줄·⑩ 입력 안내·4c orders 쓰기는 read·core가 이미 뺐고 대시보드 core에는 확인 대기 표시를 붙였다
