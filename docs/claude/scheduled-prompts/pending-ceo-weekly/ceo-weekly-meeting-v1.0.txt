R1 관제판의 예약 작업 기록이 실제와 다름 — 관제판 예약 기록(schedules)의 trigs에 적힌 예약 작업 id로 짝을 지은 뒤, 예약 작업 수정 시각이 관제판 기록보다 30분 넘게 새롭거나, 지시문 앞부분의 버전(v숫자)이 관제판 표기(이름의 v숫자, 없으면 text의 "지시문 v숫자")와 다르거나, 짝이 없는 예약 작업(켜져 있는 반복 예약 또는 "개장 전 이벤트"로 시작하는 일회성)·trigs가 비어 있는 관제판 항목이 있을 때. 이름에 "Windows 작업" 또는 "GuardedPortfolio"가 든 관제판 항목은 Claude 예약 작업이 아니라 제외하고, 그 밖의 단발성·종료 예약은 건수만 센다. 목록을 끝까지 읽지 못하면 R1은 점검하지 않고 "R1 미점검"으로 낸다.
R2 작업이 가리키는 문서(docs/claude)가 작업 갱신 시각보다 30분 넘게 새로움, 또는 문서를 찾지 못함(문서 목록 읽기가 실패한 주는 ceo.py가 R2 줄을 세지 않고 "R2 미점검"으로 둔다).

R5 "지금 할 일" 후보가 없음 / 후보들의 추천 순서 숫자가 같음.
R6 진행 중인데 7일 넘게 갱신 없음.

ceo.py가 하는 일(판정 기준, 바꾸지 않는다): 사건 기간 = 직전 일~토, 코어 날짜 = 화~토. 운영관리 = 날마다 auto-core result.json·decision.json 상태(둘 다 OK = 정상, 없음·FAIL = 🔴, HOLD 등 = 🟠, 사유는 ':' 앞 코드만), 코어가 사람에게 요청한 일(키움 입력 제외), PC 상태 점검(auto_logon WARN 단독 제외), 관제판 점검 발견·미점검. 투자리서치 = 날마다 연구 기록 상태, 공식 사실 수, 이번 주 카드 수락·관심 명단 변경. 연구개발 = 관제판 작업 상태(진행 ≤3, k가 '권한'·'K3'로 시작하는 진행 ≤1), 이번 주 완료, 최근 개발 실행, 채점 WEEKLY_LATEST(일요일 날짜가 아니거나 status가 OK가 아니면 발견). 법률 = CLAUDE.md·AGENTS.md 크기·sha256을 지난 보고의 ceo-state와 비교, 정책 파일 수정 이름, 이번 주 수정된 예약 작업 수(목록을 끝까지 못 읽으면 "확인 필요"). 감사실 = 이번 주 Judge 보고서의 마지막 VERDICT 줄(같은 작업에 PASS가 있으면 FAIL을 발견으로 세지 않음), 날마다 독립 대조 verdict(MISMATCH·ERROR = 🔴), C1 누계는 관제판 redesign-t2 next의 "C1 … n/10" 부분 인용(금액 가림). 보고 파일 전체의 결정 중 "답:" 줄이 없고 기한이 TODAY보다 앞선 것만 5절에 "기본값 기록"(현행 유지)으로 닫는다(한 번만). 기한이 남은 것은 4절에 "답 대기"로 다시 보인다. 같은 날 보고가 이미 있으면 abort. 회사 상태 = 🔴(코어 없음·FAIL 또는 독립 대조 불일치·오류) / 🟠(그 밖의 발견) / 🟢(발견 없음). 결정 건수가 3주 연속 늘면 "팀 제안 기준 점검 필요" 1줄.
