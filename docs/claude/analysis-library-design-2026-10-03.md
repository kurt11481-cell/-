# 분석 라이브러리 설계 초안 (2026-10-03)

## 0. 결론 (먼저)
- **타당성 판정(2026-10-03): 부분 타당.** 중복 재검토 문제는 실재하지만, "라이브러리/아카이브"라는 새 층을 한 번에 만드는 것은 지금은 과하다. 가장 큰 낭비는 "결과가 저장 안 됨"보다 "긴 원문을 매번 통째로 읽음"이라서, 먼저 줄이고(REMOVE) 있는 것을 연결한 뒤(REUSE), 실측으로 이익이 확인될 때만 더한다(ADD).
- **아카이브(옛 문서 옮기기·전부 보관)는 하지 않는다.** 보관을 늘리는 것은 읽을 양을 줄이지 않는다. 대체된 문서는 머리말 status만 바꾼다.
- 새 DB·새 서브시스템은 만들지 않는다. 이미 있는 산출물(SAVE 메모, 외부 주장 원장, 관심 명단 파일, 대시보드 저장소)을 그대로 쓰고, 필요가 확인된 것만 **색인 → 공식 사실 기록 → 종목 요약판** 순으로 얹는다.
- 라이브러리는 캐시이지 권한이 아니다: 근거 등급을 올리지 못하고, 가격·계좌는 항상 키움을 새로 조회한다.

### 0-1. 타당성 검토 근거 (NO_CHANGE → REMOVE → REUSE → REPLACE → ADD)
| 순서 | 검토 | 판정 |
|---|---|---|
| NO_CHANGE | 원장·명단 파일·SAVE 메모는 이미 공용으로 연결됨 | 일부 이미 해결 — 이 부분은 새로 만들 필요 없음 |
| REMOVE | 통합 점검이 카드 묶음(108,755B) 중 2~8·10절·결정 절 ≈ 93,400B(86%)를 매일 읽음. 트리거 정의는 예약 지시문에 이미 있음 | **가장 큰 이익, 비용 거의 0** — 매일 읽기를 kill 기준 줄·매수 근거 표(5-x-1·6-1)·7·10절·결정 절(≈20,700B)로 줄이고 전체 읽기는 카드 수락 때만 |
| REUSE | 대시보드 runs(ArtifactData)는 Cowork·예약 작업에서 이미 조회 가능(v3.5 0단계 방식) | 점검 상태 파일 미러는 보류, 먼저 이 조회 방식 재사용 |
| REPLACE | 흩어진 리뷰 결과 → 원장 병합(리더십 §6 초안 등) | 기존 원장 절차로 처리, 새 구조 불필요 |
| ADD | 색인(현행 문서 포인터), 공식 사실 기록, 종목 요약판, 자동 생성 스크립트 | 색인만 먼저(작음, 수동). 나머지는 실측 이익 확인 뒤 |
- 미검증: 실제 토큰 절감량(바이트는 확인, 토큰 환산·실행당 사용량은 확인 필요).
- 위험: 새 층은 유지 부담·낡은 요약 재사용 위험을 만든다(7절). 커널 원칙 "Hot-Path blocker 해결 전 새 subsystem 금지, 복잡도는 검증 가능한 이익이 있을 때만"과 충돌하지 않게 단계적으로만.

## 2. 구조 (기존 3층 + 색인)
- L0 원천 캐시(있음, 변경 없음): PDF .md 캐시, SAVE web-feed 이력, 키움(캐시하지 않음).
- L1 기록(추가 전용): 외부 주장 원장(있음) · 관심 명단 파일(있음) · **공식 사실 기록 `library/facts.jsonl`(신규)** · **점검 상태 `library/state/check-latest.json`(신규, 대시보드 기록과 같은 내용)**.
- L2 판단 문서(있음): 카드·M6·리더십·리뷰 — 표준 머리말만 추가.
- L3 색인(신규): `docs/claude/library/INDEX.md`, `docs/claude/library/tickers/<티커>.md`.

### 2-1. 표준 머리말 (새 분석 문서 맨 위, 이 문서 머리말이 예시)
id · type(card|m6|leadership|external-review|market-memo|design) · status(current|superseded|draft) · supersedes · as_of(근거 시점) · valid_until · tickers · evidence_grade(A~D) · summary(5줄 이내).

### 2-2. INDEX.md
- status=current 문서만 1줄: 종류 | 종목 | as_of | 유효기한 | 경로 | 한 줄 요약.
- superseded는 맨 아래 "보관" 절에 경로만(파일은 옮기지 않는다 — 기존 참조 경로 보존).

### 2-3. 종목 요약판 tickers/<티커>.md (종목당 40줄 이내)
현행 카드(경로·판정·as_of) / 최근 점검 상태(충족·근접 트리거, 점수판) / 공식 사실 최근 5건 / 열린 외부 주장(ID·확인일) / SAVE 언급 최근 7일(제목만) / 명단 점수(R2.1) / 다음 이벤트 / 오래된 항목 표시.

### 2-4. 공식 사실 기록 facts.jsonl
- 한 줄 = 한 사실: ticker, kind(earnings_date|8k|press|filing), fact, url, published_at, verified_at, by.
- 공식 출처로 확인된 것만. 보도·SAVE·커뮤니티는 넣지 않는다(그건 외부 주장 원장).
- 사용: WebSearch 전에 이 파일에서 그 종목 최근 사실을 보고 "그 이후" 것만 검색.

## 3. 읽기 순서 규칙 (모든 분석·예약 작업 공통)
1. INDEX.md → 2. tickers/<티커>.md → 3. 원문은 필요한 절만(`grep -n "^#"`로 헤딩 찾고 범위만 읽기) → 4. 원천 재조회는 요약판에 없거나 유효기한이 지났을 때만. 가격·계좌는 항상 키움 재조회.
5. 과거 판단 재현은 as_of ≤ decision_as_of 항목만 쓴다.
6. 색인·요약판을 못 읽으면 기존 방식(원문 읽기)으로 진행한다. 점검 불완전 사유가 아니다(Cold Path 장애가 Hot Path를 막지 않게).

## 4. 쓰기 규칙 (한 층 = 한 작성자)
| 작성자 | 쓰는 곳 |
|---|---|
| SAVE 작업 | 시장 메모(기존 그대로) |
| 통합 점검 | check-latest.json, facts.jsonl 추가(쓰기 예외 — 사용자 승인 필요) |
| 외부자료 처리 | 원장(사람 수락 뒤, 기존 그대로) |
| 주간 발굴 | 명단 파일(기존), facts.jsonl 추가 |
| Cowork 카드 작성 | 카드 문서 + 머리말 |
| 색인 | build_library.py만(사람·LLM은 직접 고치지 않는다) |

## 5. 안전 경계
- 요약은 원문 등급을 넘지 못한다(D는 요약에서도 D). RESEARCH_FINDING != PRODUCTION_POLICY.
- 요약판의 가격·계좌 수치는 참고용, 판단은 키움 재조회 값으로.
- 외부 주장 강도 0 유지. facts.jsonl에는 공식 출처만.
- 실행 권한 변화 없음(order_authority=false). 정책·상태 파일 수정 없음.

## 6. 적용 순서 (한 번에 하나, 단계마다 사용자 확인) — 타당성 검토 반영
0. **REMOVE, K1(예약 지시문 문구), 승인 필요**: 통합 점검의 카드 묶음 읽기를 kill 기준 줄·매수 근거 표(5-x-1·6-1, 매수 요건 ③용)·7절·10절·결정 절로 축소(≈93KB → ≈21KB/실행, 약 78% 감소). 카드 대 지시문 불일치 확인은 카드 수락·변경 때 Cowork에서 1회. v3.8(관심 명단 확장)과 묶어 지시문을 한 번만 바꾼다. → 초안 작성(2026-10-03): `integrated-check-v3.8-change-2026-10-03.md` — 실측 평소 읽기 ≈145KB → ≈85KB(지시문 포함).
1. **ADD 최소, K0(코드 없음, Cowork)**: 현행 문서에 머리말 추가 + INDEX.md(현행 문서 포인터 1줄씩) 수동 작성. 보유 종목 현행 카드 확정(8절)도 여기서. 검증: 다음 분석 1건(첫 주간 발굴 또는 PWR·LITE 카드 수락)을 INDEX로 시작해 읽은 바이트 비교.
2. **실측 뒤 결정**: 같은 실적일·공식 발표 WebSearch 반복이 실측으로 확인되면 facts.jsonl(통합 점검·주간 발굴 쓰기 예외, 승인 필요).
3. **실측 뒤 결정**: 수동 INDEX 갱신이 부담이 되면 종목 요약판 + build_library.py(K2, Claude Code)로 자동 생성. check-latest.json 미러도 이때 판단.
- 하지 않음: 옛 문서 이동·전부 보관하는 아카이브, 별도 DB, 새 예약 작업.

## 7. 왜 틀릴 수 있나
- 낡은 요약판에 판단이 고정될 위험 → 유효기한·오래됨 표시, 가격 항상 재조회.
- 색인 유지가 새 운영 부담이 될 위험 → 3단계 자동화 전까지 수동 갱신은 카드 수락 때만.
- 절 단위 읽기로 문서 안 모순을 놓칠 위험 → 카드 수락 때는 전체 읽기.
- 절감 규모는 실측 전 추정 → 1단계 바이트 비교로 확인.

## 8. 확인 필요
- 예약 실행 1회당 실제 토큰 사용량(현재 측정 수단 확인 필요).
- 보유 종목 현행 카드가 integrated-stock-cards v2인지, mvll-holding-card / soxl-nbis-holding-cards인지 머리말로 확정 필요.
- 통합 점검 v3.7 대상(AMD 포함)과 명단 파일 members(MU·BE·DELL·PWR·LITE)의 차이 — v3.8 적용 전 의도된 상태인지.
