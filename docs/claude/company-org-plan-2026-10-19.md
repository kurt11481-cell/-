# 투자_V2 운용회사 — 조직·운영계획 (2026-10-19, 사용자 요청)

사용자 요청(2026-10-19 11:31): "이 주식 시스템은 앞으로 하나의 회사(펀드 운용 회사)이다 … 연구개발팀, 운영관리팀, 법률팀(시스템 지침 검토 및 수정), 위원회 등등 … 각 팀의 팀장들이 팀내 제안 의견 취합하여 팀장회의 진행하여 사장(사용자)에게 보고한다."

## 0. 결론

- **조직은 새 일을 만드는 게 아니라, 이미 도는 자동 작업(README 기준 반복 예약 9개 · Windows 작업 8개 · 스킬 · 수시 세션)에 팀·팀장·보고선을 붙이는 것**이다. 새 절차를 늘리면 재설계가 짚은 근본 원인 R5 "거버넌스 자기 증식"(automation-redesign-2026-10-10.md:46)이 다시 생긴다.
- **구성**: 사장(사용자) · 4팀(운영관리 · 투자리서치 · 연구개발 · 법률) · 감사실(독립 Judge, 사장 직속) · 리스크·권한위원회 · 주간 팀장회의.
- **보고**: 매일 = 지금의 08:50 자동 운영 코어 결과 알림이 "운영 일보"(예외·행동 있을 때만). 매주 = **주간 경영보고 1장**(일 09:47), 사장 결정은 **개수 제한 없이 기준으로 거름**(바꾸자는 제안만 결정, 급한 것 먼저), 답이 없으면 기본 처분(현행 유지).
- **늘지 않는 것**: 일상 사람 손 +0/주(읽기는 선택), 예약 작업 순증 0(관제판 주간 점검 작업을 회의로 바꿔 씀), 권한·한도·주문 단계 변화 0.
- **결정 한 줄**: `결정 org-setup: Q1 a, Q2 a, Q3 a` (10절). 답이 없으면 이 문서만 보관하고 아무것도 바꾸지 않는다.

## 1. 설계 원칙 (근거)

| # | 원칙 | 근거 |
|---|---|---|
| P1 | 조직 ≠ 권한. 팀은 지금 있는 권한만 나눠 갖는다. 시스템은 자기 권한을 스스로 넓히지 못한다 | 헌법 §14·§31 |
| P2 | 일상 사람 손 목표 0(주문 2단계 전 키움 주문 입력만 예외). 제안마다 주당 사람 손 비용을 적고 일상 손을 늘리지 않는다 | CLAUDE.md:16, :95 |
| P3 | 매일 판정은 결정론 코어가 한다. 팀장회의·보고는 Cold Path라 실패해도 코어는 돈다 | 헌법 §25, CLAUDE.md Goal(:10~16) |
| P4 | 분리 유지: Builder ≠ Judge, 전략 ≠ 리스크 승인, 감사 결과는 팀이 걸러내지 않는다 | 헌법 §13, CLAUDE.md:108 |
| P5 | 최소 구조: NO_CHANGE → REMOVE/SIMPLIFY → REUSE → REPLACE → ADD. 새 필드보다 파생 보기 | 헌법 §24 |
| P6 | 기본 처분: 기준 미달·무응답 = 현행 유지, 변경을 제안할 때만 묻는다 | CLAUDE.md:93 |

## 2. 조직도

```
                              사장 (사용자)
            ┌────────────────────┼─────────────────────┐
     감사실 (독립 Judge)    리스크·권한위원회       주간 팀장회의 (의장: 운영관리팀장)
                                                         │
          ┌───────────────┬───────────────┬──────────────┴┐
      운영관리팀       투자리서치팀       연구개발팀         법률팀
   (매일 자동 운영)   (LLM 리서치)     (개발·검증·학습)   (지침·규정)
```

- **팀원** = 이미 도는 예약 작업·Windows 작업·스킬·수시 세션. **팀장** = 주간 팀장회의 예약 작업 안에서 팀마다 한 번 도는 "요약 단계"(상주 에이전트가 아님).
- 사용자가 이름을 준 것은 연구개발·운영관리·법률·위원회다. **투자리서치팀은 추가**했다: 코어가 받는 유일한 LLM 입력(연구 기록)과 카드·관심 명단을 맡는 일은, 매일 도는 결정론 코어(운영관리)와도 코드를 고치는 개발(연구개발)과도 권한·실패 영향이 다르다(CLAUDE.md Hard safety "The only LLM input to the auto-core is the research record"). 합치는 안은 10절 Q1 b.
- **투자위원회(주문별 위원회)는 두지 않는다**: 2026-10-10 재설계로 주문표는 결정론 관문이 판단하고, 위원회는 정책·한도·권한 변경에만 쓴다(CLAUDE.md:89).
- 켜져 있는 **일회성 예약**(이벤트 점검·재검토 예약 등)은 이름으로 팀에 배정한다: 이벤트·종목 재검토 → 투자리서치, t2-rc 켜 조건 점검 → 연구개발(감사실이 숫자를 원문 그대로 옮김).

### 3-4. 법률팀 — 회사의 법(지침·규정)
- **임무**: 지침 층(헌법 · claude.ai 프로젝트 지침(커널) · CLAUDE.md · AGENTS.md · 프로젝트 메모리 · 스킬 · 예약 지시문)의 충돌·중복·낡은 규칙을 찾아 **개정안**을 낸다. 새 제안이 안전 경계(권한·한도·fail-closed·매도 비차단)를 어기는지 사전 검토한다.
- **팀원**: context-layer-audit 스킬(문서 역할 점검·품질 저하 12층, 읽기 전용) · loop-design-check 스킬(반복 루프 점검) · 검토 안정성 규칙(review-stability-2026-10-13.md) 관리.
- **팀장이 매주 읽는 것**: 지침 파일의 크기·수정 시각(device_list_dir, 지난 보고 값과 비교 — 예약 세션은 device_bash를 피한다, dev-board-weekly-review.txt:13): CLAUDE.md · AGENTS.md · workspace/policies/ · stock-strategy-system/alert_policy.json(정책은 이름·크기·시각만, 내용 읽기 금지 — 금지 목록에 이 예외 1줄). 예약 지시문 변경은 list_triggers의 updated_at(지난 보고 뒤 수정 n건)으로 본다 — scheduled-prompts/ 폴더는 보관 사본이라 대조용.
- **월간 지침 점검**: context-layer-audit 문서 역할 점검을 예약 세션에서 부를 수 있는지는 확인 필요(예약 지시문 중 스킬을 부르는 것 0개). 1단계 시험 실행에서 확인되면 매월 첫 회의에 넣고, 안 되면 Cowork 수시로 한다.
- **할 수 있는 것**: 읽기 전용 진단, 개정 문안 작성.
- **할 수 없는 것**: 개정 적용(사장 승인 뒤 Cowork가 적용 — 헌법·커널은 사용자가 claude.ai 프로젝트에 붙여 넣음), 정책 파일 수정(정책 = 권한·한도 변경 = 위원회 + 사장).
- **정리 안건은 redesign-t4로**: 재설계 T4가 이미 docs/claude → archive/ + 정본 3개(SYSTEM·RUNBOOK·DECISIONS)와 CLAUDE.md 낡은 줄 정리를 계획한다(automation-redesign-2026-10-10.md:145, 관제판 redesign-t4 next ③⑥). 법률팀은 따로 정리 흐름을 만들지 않고 정리 안건을 보고 파일에 쌓아 두었다가 T4 착수 때 입력으로 넘긴다(T4는 T2 "켜" 뒤라 시점이 정해지지 않음). 충돌·안전 경계 위반은 T4를 기다리지 않고 바로 개정안 → 사장 결정.
- **주간 지표**: CLAUDE.md 크기(2026-10-19 17,515바이트 — 10/10 재설계 진단 때 "약 11KB") · 이번 주 지침 파일 변경 n건 · 미해결 충돌 n건.
- **관제판 stream**: 새 stream을 만들지 않는다. 법률 작업이 적어 system stream에서 제목 머리 "[법률]"로 충분하다(새 stream은 streams 문서 1개로 가능하지만 색이 --s1~--s5 다섯 개라 겹침).

### 3-5. 감사실 — 독립 심사 (사장 직속)
- **팀원**: 독립 Judge(파이프라인 헤드리스 Judge · 수동 경로 별도 세션) · 내장 재검토 subagent(검토 안정성 V5).
- **규칙**: 파일을 고치지 않는다. Judge 판정과 2차 대조 숫자는 팀장회의가 요약하거나 거르지 않고 **원문 그대로** 보고서에 옮긴다(감사 대상 팀이 감사 결과를 편집하지 않게).
- **주간 지표**: Judge 판정 PASS/FAIL n건 · 2차 대조 이번 주 일별 verdict 원문(MATCH·MISMATCH·NOT_CHECKED·ERROR·결과 없음) · C1 누계는 관제판 redesign-t2 next 문구를 그대로 인용(t2rc-check.json에 누계 칸이 없어 회의가 세지 않는다).

### 3-6. 리스크·권한위원회
- **구성**: decision-council 스킬(설계자·회의론자·실용주의자·비판자).
- **소집**: 정책·한도·권한 변경 제안일 때만. 주문표·카드에는 소집하지 않는다(CLAUDE.md:89).
- **권한**: 낮추기·유지·확인 요구만. 승인은 사장, 매매 근거 아님.

### 3-8. 받은 결과 (v1.3, 2026-10-19 — 팀장이 매주 빠짐없이 확인)
- 위 "팀장이 매주 읽는 것"은 v1.3부터 주간 팀장회의 스크립트(docs/claude/scheduled-prompts/ceo-weekly/ceo.py)가 원본에서 뽑은 **받은 결과**(S-번호)로 전달된다. 팀장은 S-번호마다 특이 없음 / 제안 있음 / 확인 필요로 답한다(보고 2절).
- 운영관리: 예약 작업 출근부 · 자동 운영 코어·결과 알림 · 통합점검 실행 상태 · 개발 관제판 점검(R1~R6) · PC 상태 · 이번 주 운영 문서.
- 투자리서치: 통합점검 내용 · SAVE 시장환경 메모 · 외부 자료 PDF 원장 · 코어 알림 내용 · 관심 명단 주간 재채점 · Next 샌디스크 발굴 · 개장 전 점검 기록 · 이번 주 리서치 문서.

## 5. 보고·결재 흐름

### 5-1. 주기

| 주기 | 무엇 | 누가 |
|---|---|---|
| 매일 | 자동 운영 루프 + 운영 일보 | 운영관리팀(기존 작업) |
| 매주 일 09:47 | 직전 보고 읽기 → 팀장 요약 4개 → 팀장회의 → 주간 경영보고 | '주간 팀장회의' 예약 작업 1개(지금 관제판 주간 점검 작업을 바꿔 씀) |
| 매월 첫 회의 | 법률팀 지침 점검(스킬 호출이 시험에서 확인된 뒤에만) | 같은 작업 |
| 수시 | 사장 직접 지시, 긴급 알림, 위원회(정책·한도·권한 변경 때만) | Cowork |

일 09:47인 이유: 일 09:20 결정 일지 채점(제한 15분)이 끝난 뒤라 한 주 자료가 모두 모이고, 정시를 피한다.

### 5-2. 제안 → 사장까지
1. **직전 보고 읽기**: 지난 보고의 4절(결정)·5절(대기열). 4절에서 "답:" 줄이 없는 D만 기한 지난 것으로 보고 기본값(현행 유지)을 이번 보고 5절에 기록한다(답한 D를 덮어쓰지 않게).
2. **팀원**(자동 작업)이 쓴 결과 파일을 팀장 요약 단계가 읽는다 — 팀원 작업은 지금 그대로.
3. **팀장 요약**: 팀마다 상태 1줄 · 지표 3개(스크립트 계산) · 제안 최대 3개(각각 기본 처분).
4. **팀장회의**: 중복 제거 → 우선순위 규칙(5-3) → 슬롯 배정(5-4).
5. **주간 경영보고**를 파일 1개(docs/claude/ceo-weekly-report.md)에 그 주 절로 덧붙이고, docs/claude/_pending/ceo-weekly-<날짜>.txt로 23:30 자동 커밋. 주마다 새 파일을 만들지 않는다(docs/claude 최상위 파일 385개·하위 포함 476개·8.1MB로 늘었고, T4가 정본 3개로 줄일 계획이라). 푸시는 실행당 1건(10절 Q3).
6. **사장 답**(선택): Cowork 아무 세션에 `결정 ceo-<날짜>: D1 a, D2 b`. 받은 세션이 docs/claude/ceo-weekly-report.md의 그 주 4절을 읽고, 해당 D 아래에 "답: <원문>(<시각>, Cowork)" 1줄을 쓰고(_pending 커밋), 반영하고, 필요한 관제판 작업을 만들거나 고친다.
   - 관제판 규칙 3절 결정함에 1줄 추가(1단계, 문서만): "`결정 ceo-<날짜>:`는 관제판 작업이 아니라 docs/claude/ceo-weekly-report.md 그 주 4절을 가리킨다. 기한 지난 ceo 결정의 기본값(현행 유지만)은 다음 주간 회의가 보고 5절에 기록한다(Cowork 기록의 예외, 정책·상태·권한·주문은 기본값으로 바꾸지 않음)."
   - 결정이 두 곳(관제판 결정함 + 보고 4절)이 되지 않게, 보고 4절 머리에 "관제판 결정함 대기 n건(id·기한)"을 함께 적는다.

### 5-3. 우선순위 규칙 (재량이 아니라 순서표)
헌법 §3: 필수 안전 경계(권한·자료 무결성 등)가 막고 있으면 그것부터, 그다음 1 자동 운영 → 2 의사결정 지원 → 3 판단 품질 → 4 리플레이·학습.
1. 안전 경계·자료 무결성 결함
2. 자동 운영 루프 구축·유지(사람 손이 생긴 막힘 먼저)
3. 포트폴리오 의사결정 지원
4. 판단 품질
5. 리플레이·학습

같은 순위면 사람 손을 더 줄이는 것 → 더 작은 변경 순.

### 5-4. 슬롯 (넘치면 다음 주 대기열 = 보고 5절)
- 진행 중 개발 ≤ 3, 권한·한도 변경 ≤ 1 (CLAUDE.md:95 그대로)
- 사장 결정: 개수 제한 없음(2026-10-19 12:47 사용자 "그렇게 해" — 고정 상한은 중요한 결정을 1주 미룰 수 있음). 대신 ① 자격: 정책·한도·권한·예약 작업·코드를 바꾸자는 제안만 결정(D)으로 올리고, "현행 유지" 권고는 알림만(CLAUDE.md:93) ② 순서: 다음 회의 전 기한 → 5-3 순서표 → 기한 가까운 순 ③ 급한 것: 다음 회의 전에 답이 필요한 D는 푸시 맨 앞 "⚠ 이번 주 답 필요 n건" ④ 감시: D 건수를 보고 머리에 표시하고 2단계 ⓑ로 평가, 많아지면 숨기지 않고 "팀 제안 기준 점검 필요"로 알림

### 5-5. 긴급은 기다리지 않는다
안전·자료 결함은 지금처럼 코어가 fail-closed로 멈추고 08:50 알림이 바로 알린다. 주간 회의는 긴급 경로를 늦추지 않는다.

### 5-6. 회의가 하지 않는 것
관제판 쓰기(dev-dashboard-protocol.md:12~13 — 예약 작업은 관제판에 쓰지 않음), 정책·상태·예약 작업·주문 변경, 카드 수락, 사장 대신 결정, 키움 조회·비밀 파일·정책 파일 읽기(지금 관제판 주간 점검 v1.2의 금지 목록 5~11행을 그대로 옮김).

## 8. 하지 않을 것 (기각)
- 팀장마다 예약 작업(팀장 4개 + 회의 1개) — 작업·토큰 증가, R5.
- 주문별 투자위원회 — 재설계가 없앤 단계(CLAUDE.md:89).
- 회의가 관제판에 결정 작업을 직접 쓰기 — 결정함 하나로 모이는 장점은 있으나 "예약 작업은 관제판에 쓰지 않는다"(protocol 1절 3)를 깨므로 지금은 기각, 2단계 평가 때 다시 본다.
- Haiku 팀장 — 우선순위 판단이 들어가 Haiku 사용 규칙 밖(CLAUDE.md:80).

## 9. 위험과 반대 의견
- **R5 재발**(회의가 매주 제안을 쏟아냄): 결정 자격(바꾸자는 제안만)·건수 표시·기본 처분·2단계 되돌림 기준. 개수를 잘라 숨기지 않는다(사용자 2026-10-19 12:47).
- **LLM 요약 오류**: 지표는 스크립트 계산, 감사 숫자·관제판 점검 출력은 원문 그대로, 운용 숫자는 코어 파일에서 복사만.

- **비용**: 주 1회 실행 토큰 — 확인 필요(1단계 시험 실행에서 잼).
- **가장 강한 반대**: "이미 관제판·알림이 있는데 보고 1장이 더 필요한가" → 그래서 새 작업을 더하지 않고 관제판 주간 점검 작업을 바꿔 쓰며, 4회 뒤 효과가 없으면 되돌린다.
