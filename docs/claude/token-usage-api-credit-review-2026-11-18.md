# 토큰 사용량 줄이기 + API 월 크레딧 활용 재검토 (token-usage-1118)

**첫 줄(부딪히는 결정):**
- room-alert-1101(active-decisions.md 59행)·room-digest-1101(60행)·election-crash-1106 C(139행)·info-collect-1107(72행)은 "예약이 그 스레드를 깨운다"로 정해져 있다. 아래 T1a·T1b는 지시문·일정·스레드를 그대로 두므로 이 네 결정과는 부딪히지 않는다. T3(가벼운 새 스레드로 옮기기)은 부딪힌다 → 지침 4절 ① 승인이 필요하고, 지금은 제안만 한다.
- **T1b(스레드 안에서 모델 바꾸기)는 규칙 두 곳과 부딪힌다:** CLAUDE.md Session hygiene "Never suggest switching model mid-session (it rebuilds the prompt cache)"와 프로젝트 지침 7절 "스레드 안에서 갈아타게 하지 않는다". 그래서 T1b는 권장이 아니라 **사장 예외 선택지**로만 올린다. 추론 노력 변경(T1a)은 같은 조항이 Claude Code의 Opus 5.5·Sonnet 5.5에서 허용한다("Effort may change mid-session only in Claude Code on Opus 5.5 / Sonnet 5.5").
- 앞선 토큰 검토 3건과 겹치지 않는다: skill-token-review-2026-10-02(스킬 상시 비용 약 2,480토큰, '현재 상태 유지')·vscode-usage-2026-10-20은 다시 열지 않는다. prompt-caching-review-2026-10-09 2절은 "예약 작업은 실행마다 새 세션"을 전제로 NO_CHANGE였는데, 11/01부터 생긴 사장실 예약 7개는 **같은 스레드를 계속 깨운다**(scheduled-prompts/README.md 24~25행 '사장실 회사PC 스레드 세션') — 바뀐 입력은 이것 하나다.

## 0. 결론

1. **토큰이 가장 많이 새는 곳은 '예약이 깨우는 스레드'다.** 예약 7개가 오래된 스레드 3개를 하루 10번쯤 깨우는데, 세 스레드 모두 Opus 5.5이고 두 곳은 추론 노력이 xhigh다. 깰 때마다 쌓인 대화 14만~33만 토큰을 다시 읽는다. 파일 줄을 옮겨 적는 알림 1건이 깰 때마다 정가 환산 $0.74~0.91이다(1절).
2. **규칙과 부딪히지 않는 가장 싼 조치는 추론 노력 낮추기다(T1a, 사장님 메시지 2줄).** xhigh로 도는 두 스레드만 낮춘다. 모델까지 Sonnet으로 내리는 길은 둘이다: 스레드 안에서 바꾸기(T1b — 빠르지만 규칙 예외) 또는 새 스레드로 옮기기(T3 — 규칙대로지만 예약 변경 승인 7건).
3. **API 크레딧은 거의 안 쓰고 있다.** 11/18 09:22 KST Console: 잔액 US$98.85 / US$100.00, **2026-12-02 09:00 KST에 만료**(앞 달 지급분은 '만료됨' — 이월되지 않음). 쓴 돈 $1.15는 시범 1 호출 6번과 맞는다.
4. **11/06에 정한 시범 4개 중 1개만 돌고, 나머지는 11/07부터 멈춰 있다.** 사장 결정이 필요한 게 아니라 연결이 끊긴 것이다: 관제판에 작업이 없어서 아무도 다음 작업(llm-news)을 올리지 않았고, 시범 1 채점도 1일차 뒤로 5일치가 밀렸다(3절).
5. 크레딧을 다 쓰는 것이 목표는 아니다. **구독 한도를 실제로 덜 쓰게 해 주는 일만** 옮긴다. 후보는 하나: 닫아 둔 B(검토 완결 재검토를 API로) 다시 열기. 재검토 1회차 약 23만·2회차 약 17만 토큰이 구독 대신 크레딧에서 나간다는 것은 그 문서의 추정이고(1절 1 (가)), 실제 이득을 보여 줄 자료는 아직 없다. 같은 Opus라 맹점도 그대로다. 다시 열 조건 중 맞는 것은 '사장 요청'뿐이다.

### 11-3. `/advisor` — 무엇이고 여기에 맞는가

확인한 사실(공식 문서): 주 모델이 일하다가 중요한 지점(방향을 정하기 전·같은 오류가 되풀이될 때·끝났다고 하기 전)에 더 센 모델에게 스스로 묻는 기능이다. 조언 모델은 대화 전체를 읽는다. 부르는 때는 모델이 정하고, 횟수를 막거나 강제하는 설정은 없다. 짝 규칙: 조언 모델은 주 모델과 같거나 높아야 한다(Sonnet 5.5 주 모델 → Fable·Opus 5 이상·Sonnet 5.5, Opus 5.5 → Fable·Opus 5 이상, Fable 5.2 → Fable 5.2뿐). 사용량은 요금제 한도에 들어가고, Fable 조언은 요금제에 따라 사용 크레딧으로 청구된다. 켜고 꺼도 주 모델 캐시는 깨지지 않는다. 다만 조언 모델이 대화를 읽는 몫은 캐시되지 않아 부를 때마다 대화 전체를 새로 읽는다(긴 스레드일수록 1회가 비싸다). 하위 작업자도 설정된 조언 모델을 물려받는다(Haiku 작업자도 Opus 조언을 부를 수 있음). 쓰는 곳: 터미널·데스크톱 앱·Remote Control·Agent SDK·`-p`. 설정은 사용자 설정 `advisorModel`, 끄기는 `/advisor off`. 시험 기능이라 동작·요금이 바뀔 수 있다. **클라우드 세션(이 프로젝트 스레드)·Cowork·예약 작업에서 되는지는 문서에 없음 = 확인 필요.**
