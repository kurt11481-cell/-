## 1. 원인
1. R1이 이름 키워드("주간"·"관제판" 등)로 짝을 지어 관심 명단·Next 샌디스크가 "관제판 주간 점검" 기록과 묶였다. 키워드가 없는 예약 6개(코어 알림·이벤트 점검·월요일·일회성 이벤트 등)는 "없음"으로 잡혔다.
2. 관제판의 Windows 작업 8개는 Claude 예약 목록에 없어 매주 "없음"이 된다.
3. 예약 목록이 응답 크기 때문에 페이지당 2~19건으로 끊기는데(19건=4페이지) 일부만 읽어도 완료처럼 비교했다. 관제판 예약 기록도 3~5건만 읽었다.
4. head(지시문 앞 200자)를 요약해 넣으면 버전 비교가 흔들린다.

## 2. 변경 (R2·R4·R5·R6 코드는 그대로)
- R1 짝짓기: 관제판 schedules 문서의 `trigs`(예약 작업 id 배열)로만 짝짓는다. 이름 키워드 표(KEYS) 삭제.
- 제외: 이름에 "Windows 작업"·"GuardedPortfolio"가 든 관제판 항목은 건너뛰고 건수만 센다. 꺼진 예약·"개장 전 이벤트"가 아닌 일회성 예약도 건수만 센다.
- 버전 비교: 관제판 이름의 v숫자, 없으면 text의 "지시문 v숫자".
- 완료 확인: 예약 목록·관제판 예약 기록을 next_cursor 끝까지 읽지 못하면 R1은 "R1 미점검"으로 낸다(불일치로 잘못 알리지 않음). 예약 목록은 limit 100·필터 없음, head는 원문 그대로.
- 보고에 "R1 제외 N건" 한 줄 추가.
