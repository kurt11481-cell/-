## 4. 쓰는 규칙
1. 쓰는 주체: Cowork만(ArtifactData, 사용자 계정). 예약 작업·Claude Code·Judge는 orders를 쓰지 않는다. 통합점검이 orders를 읽는 것은 v3.12(전날 지시 결과 1줄) 승인 뒤의 일이다.
2. 시점: SHADOW 시범은 봉인 절차 3단계(사용자가 자기 결정을 적고 지시서가 공개된 뒤)에만 기록한다. 봉인 중에는 쓰지 않는다(채팅에 해시만). 공식 지시서는 발행 때 기록한다. 사용자 수동 결정 지시(`user`)는 사용자가 "진행"을 고른 직후 기록한다(2026-10-09, 9절).
3. 값: 지시서 md의 값을 그대로 옮긴다. 원본은 md, orders는 표시용 사본이다. 새 수치·판정을 만들지 않는다.
4. 결과: outcome은 다음 날 키움 읽기 조회 → 대조 제안 → 사용자 "확인 <코드>" 뒤에만 고친다. 가격 움직임으로 체결을 추정하지 않는다. 그 전에는 pending.
5. 재발행: 새 id(번호 +1). 이전 문서는 outcome으로 닫는다.
6. 삭제하지 않는다(이력). 잘못 옮긴 값은 사용자 확인 뒤 정정하고 note에 적는다.
7. 화면: pending이면 카드(입력 전 확인 3가지 포함), 그 밖은 "지난 지시" 표(접힘). 지시가 없으면 "유효한 지시 없음" 한 줄과, 선택한 점검일에 보유 종목 충족 트리거가 있으면 "지시서 발행 대상인지 Cowork에서 확인"(숫자 없음). 읽기 실패면 "확인 필요"로 보인다(조용히 비우지 않음).

## 10. 판정 유지 구간 표시 (2026-10-21, close-confirm e 병합 f8d065d · 통합점검 version 24)
- 근거: 사용자 결정 close-confirm e(2026-10-20 19:43), 병합 승인 2026-10-21 19:13, 독립 Judge PASS `close-confirm-e-judge-report.md`. 화면은 K1 표시 전용 — 새 판정·가격·수량을 만들지 않는다.
- 코어 주문표 priceCalc: `band` = 근사 종가 ±1%(옛 lo~hi), `hold` = 그 종목 평가 세션 종가만 각 센트로 바꿔도 같은 판정이 나오는 센트 구간(S7·다른 종목·현금 고정). 매수 lo~hi = hold, 매도 lo~hi = band. hold를 확인하지 못한 매수는 주문표가 없다(blocked `HOLD_RANGE_UNVERIFIED`).
- 환산 칸: 입력값이 band 밖이면 지금처럼 "범위 밖". 매수는 band 안·hold 밖이면 "판정 유지 구간 밖(<사유>) — 오늘 입력하지 않음 · 다음 아침 재판정"(가격 숨김). 매도는 가격을 보여 주고 hold 밖이면 경고 줄 "판정 유지 구간 밖(<사유>) — 매도는 막지 않음", hold.status unverified면 "판정 유지 구간 확인 필요 — 매도는 막지 않음". 규칙 줄은 "±1% band · 판정 유지 hold". hold가 없는 지시(옛·수동)는 전과 같다.
- 사유 표시: NO_TICKET:CIRCUIT_CLOSED → 그 종가면 회로 닫힘, NO_TICKET:<사유> → 그 종가면 주문표 없음 <사유>, STEP_DOWN → 단계 낮아짐, CASH → 현금 부족, G2B → 금액 상한 초과, DATA → 계산 불가. hold 끝이 센트 사이 값(예 905.415)이면 입력 가능한 센트로 보여 준다(아래 끝 올림·위 끝 내림, 판정은 저장된 값 그대로).
