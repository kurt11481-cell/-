# S7 5.4-4 U3 실측 — `ust21100` 거래내역 실제 문자열 (2026-10-02)

## 1. 결론

- 실제 입출금·환전 행은 2025-01-01~2026-10-02에 **한 줄도 없다**. 그래서 입출금·환전 적요 낱말과 환전 줄 통화코드는 **확인 불가**(실제 행 없음)다. 낱말표의 FX·TRANSFER 규칙은 추정 그대로 남는다.
- `deal_no`는 날짜마다 1부터 다시 매기는 번호이고, 관측한 행에서 (날짜, 번호) 중복은 없었다. `deal_dt`는 한국 날짜(처리·결제 반영일)로 보인다.
- 지금 코드·낱말표로 실제 문자열을 돌리면 **막힘 3건**이 나온다(5절). 가장 큰 것은 "행 없는 기간 = 오류"다. 이 계좌는 거래가 드물어 대조 간격 대부분이 빈 기간이라 증거 절차가 거의 매번 멈춘다.
- 다음: 막힘 3건을 고치는 K2(Builder) → 그 뒤 5.4-5 브로커 대조. 적용 시작(5.4-7)은 K2 병합 뒤.

## 6. K2 후보 (Builder, 권장안)

1. 응답이 `return_code` 20이고 메시지에 `501724`가 있을 때만 "행 0개"로 정규화한다. 다른 0 아닌 코드(예: 501058)는 지금처럼 실패한다.
2. 낱말표에 비외부 분류 하나를 TRANSFER보다 앞에 더한다(예: `CORPORATE_ACTION`, 낱말 `액면`, `단주대금`). `타사대체입고` 같은 다른 입출고는 그대로 UNCLASSIFIED(외부 주식 이동일 수 있음).
3. 낱말표 `status` 문구를 "배당·매매·입출고(분할·병합)·단주는 실측, 입출금·환전은 실제 행 없음(추정)"으로 바꾼다.
4. 대상 테스트: 3절 실측 문자열 7종 + 빈 응답(501724 → 0행, 501058 → 실패).
