## 3. 루프 설계 점검 (loop-design-check)

- 판정: **진행(수동 루프)**. 예약 자동화는 만들지 않는다 — 에펨코리아 자동 수집 불가, 주장 검증은 판단이 섞여 완전 자동화 불가.
- 유형: 글 단위 servo(모든 주장 행이 채워지면 종료) + 채점은 확인 시점 도래 때 1회.
- 완료 기준: 주장 행마다 {구분, 등급, 라우트, 공식 URL 또는 "확인 필요"}가 채워짐. 경계: 정책·상태 파일 불변, 트리거 변경은 제안만, 커뮤니티 해석 강도 0. 재시도 상한: 주장당 공식 출처 검색 3회. 대조: SEC·IR 원문, 키움 가격, 현금·SPY.
- 실패 1(모호한 목표) pass · 2(작성자=판정자) 확인 필요 — 채점은 카드 작성 경로와 분리된 S7b 채점기로 · 3(경계 미기재) pass · 4(실행 중 질문) 위험 — "유용 이유"를 접수 때 받고 없으면 "판단 보류" · 5(원장 비대) 확인 필요 — 한 줄 행, 분기마다 R0 정리.
- 레드라인: 작성자 점수가 근거 강도·배분에 들어가면 안 됨, 학습이 정책을 고치면 안 됨. 둘 다 위 규칙으로 차단.
