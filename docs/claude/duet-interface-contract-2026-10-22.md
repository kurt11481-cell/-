# Duet 접속면 계약 (2026-10-22)

## 0. 한 줄
Duet은 **사장과 말하는 창구**다. 읽기만 하고 아무것도 쓰지 않는다. 실행(자동 코어·키움 조회·Windows 작업·개발 파이프라인)은 PC에 그대로 있고 Duet 고장이 실행을 막지 않는다.

## 1. Duet이 읽을 것 (원본 그대로, 사본을 새로 만들지 않음)
| 읽을 것 | 원본 | 빼는 것 |
|---|---|---|
| 결정 원장 | K-1이 만들 원장(관제판 duet-k1). 그 전엔 관제판 결정함(status decision) | — |
| 작업 목록·결정 대기·멈춤 의심 | 개발 관제판 tasks(읽기만) · 비서 기록 workspace/outputs/secretary/<날짜>.md | — |
| 그날 코어 결과 요약 | 08:50 코어 결과 알림과 같은 내용 | **보유 종목·수량·금액·주문표 값**(Duet 계약에서 뺌 — 미국주식 현황판·통합점검 주문표 패널이 맡음) |
| 비서 제안 | workspace/outputs/secretary/<날짜>.md | — |
- 읽는 길(커넥터·아티팩트·GitHub 중 무엇)은 시험 ②에서 정한다. 정해지기 전엔 확인 필요.

## 2. Duet이 쓸 것 = 없음
관제판·대시보드·저장소·예약 작업·메모리 쓰기 없음. 사장이 Duet에 "○○ 해 줘"라고 하면 Duet은 **작업 요청을 Cowork로 넘기는 문장**만 만든다(넘기는 길도 시험에서 확인, 그 전엔 사장이 Cowork에 직접).

## 3. Duet으로 받을 수 없는 결정 (지금 규칙, CLAUDE.md Hard safety·Change classes)
| 결정 | 지금 유효한 곳 | 바꾸려면 |
|---|---|---|
| 결정 일지 기록(보유 카드 ADD/HOLD/TRIM/EXIT 수락) | 현재 Cowork 대화의 사장 메시지 | K-5 승인 기록(권한·한도) |
| 브로커 대조 확인 | 같음(T1 기록 모드 뒤에는 대비책) | K-5 + duet-q4-recon 판단 |
| 정책·상태 변경 승인 | 같음 | K-5 |
| 권한·한도 작업 착수 승인·병합 결정 | 같음 | K-5 |
| 일반 결정함 답(관제판 결정 `결정 <id>: …`) | 규칙 제한은 없음 — 다만 Duet → Cowork 전달 길이 없어 당분간 Cowork에서 | 시험 ②에서 전달 길 확인 |
| 예약 작업 지시문 교체 | 창구 제한은 없지만 PC 앱 승인 1번 필요 | Duet 범위 밖 |

K-5 승인 기록(secretary-agent-idea-2026-10-21.md 6-1 재사용): 사장 신원(허용 계정) + 원문 + 시각 + 제안 해시 + 만료를 기록으로 남기고, 코드가 해시·만료를 검사한 뒤에만 반영. 비서가 문구를 옮겨 적는 방식이 아님. 권한·한도 변경이라 시험 통과 뒤 설계, 승인 1줄 + 독립 Judge.
