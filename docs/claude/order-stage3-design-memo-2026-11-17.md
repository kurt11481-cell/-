# 주문 3단계(정해 둔 범위 안 자동 제출) 설계 메모 (2026-11-17)

계좌 금액·수량은 적지 않는다(비율·E만). 시각은 KST.

## 0. 결론

- **3단계는 '사장이 미리 정한 범위(봉투) 안의 주문은 승인 없이 제출, 밖이면 승인 1번'이다**(automation-redesign-2026-10-10.md 134행). 지금은 열 수 없다. 조건은 '2단계 20건 오류 0 + 미체결·중복 주문 대조 장치'와 사장의 별도 승인이다(같은 문서 133~135행).
- **사장 지시 가운데 3단계가 답하는 것**: 이미 정한 주문을 사람 손 없이 넣는 것, 넣은 주문의 접수·체결을 계속 지켜보는 것.
- **3단계로도 되지 않는 것**: 장중 시세를 보고 그 자리에서 파는 것. 지금 설계에서 판정은 하루 1번이고 주문은 종가(LOC)다. 가격을 보고 파는 규칙은 다섯 번 시험했고 통과한 것이 없다(2절).
- **설계 방향(권고이고 결정이 아님)**: 첫 봉투는 '위험을 줄이는 매도'만 담고 매수는 2단계(승인 1번)에 남긴다. 봉투의 숫자는 사장이 정한다.
- **지금 만들 것은 없다.** 3단계 부품(실시간 스트림 상시 프로세스 등)은 2단계에 필요 없고 3단계 전에 다시 본다(f-trading-infra-gap-review-2026-10-12.md 85행).
- **먼저 정할 기존 결정이 있다.** '자동 매도 없음'(ev-derisk b, 2026-10-13)이 살아 있다. 매도 봉투가 이 결정에 걸리는지는 3단계 안건에서 사장이 먼저 정한다(3절).

## 1. 2단계와 무엇이 다른가

| | 2단계 | 3단계 |
|---|---|---|
| 주문을 만드는 것 | 코어 | 코어 |
| 제출 직전 | 사장 승인 1번 | 봉투 안이면 승인 없음, 밖이면 2단계로 |
| 사장이 하는 일 | 주문마다 승인 | 봉투 설정·정지 스위치(automation-redesign 134행) |
| 저녁 주문 날 사람 손 | 승인 1번 | 0(같은 문서 93행) |
| 취소·정정 | 사람만(기본값) | 취소 자동화가 조건 |
| 감시 | 다음 날 코어가 체결 확인 | 주문·체결 스트림을 받는 상시 프로세스 |

원문: f-trading-infra-gap-review 42~43·67·73행.

## 2. 사장 지시와 3단계

사장 직접 입력(2026-11-17 11:29 KST): "시스템이 회사 자금 운영에 단순 조언 및 검토 수준을 넘어 적극적이고 지속적, 실시간으로 모니터링 및 개입해야 한다."

| 지시의 말 | 3단계에서 되는 것 | 되지 않는 것 |
|---|---|---|
| 적극적 개입 | 봉투 안 주문을 승인 없이 제출 | 시스템이 스스로 새 판단을 만들어 파는 것. 새 매매 규칙은 사전 등록 시험 통과와 사장 승인이 있어야 한다(system-evolution-2026-10-31.md 175행) |
| 지속적 | 제출한 주문의 접수·체결 확인, 미체결 정리 | — |
| 실시간 | 주문이 나간 뒤의 확인과 취소 | 장중 가격에 반응하는 매매. 판정은 하루 1번·LOC이고(f-trading-infra-gap-review 30행), 장중 돌파 매매 리플레이는 10/31 FAIL로 닫혔다(system-evolution-2026-10-31.md 256~258행) |

- 하락 때 파는 규칙의 시험은 다섯 번이다(S3·S4·a-3 ③ 손절선·개장 전 갭 매도·11/17 추세 이탈. 목록: exit1117-preregistration-2026-11-17.md 117행). 다섯째는 기준 미달로 닫혔고(active-decisions.md exit-test-1117 행), 앞의 넷도 닫힌 질문이다(같은 사전 등록 36행). 11/17 미달의 뜻은 '보유를 이긴다는 근거를 못 찾았다'이지 '손해가 증명됐다'가 아니다(exit1117-results-2026-11-17.md 19행).
- 사장은 위험을 알고 직접 규칙을 정할 수 있다(exit1117-preregistration-2026-11-17.md 119행, 미검증 표시). 그런 규칙을 봉투에 넣을지는 봉투를 정할 때 사장이 고르는 항목이고, 이 메모는 권하지 않는다.

## 3. 봉투 초안 — 칸만 두고 숫자는 비운다

원문의 봉투 4칸은 상품 목록·1회 금액·하루 회전율·노출 상한이다(automation-redesign 134행. f-trading-infra-gap-review 67행은 뒤의 3칸만 적는다). 아래는 그 칸에 설계 선택지를 더한 것이다.

| 칸 | 선택지 | 권고(첫 봉투) | 숫자 |
|---|---|---|---|
| 방향 | 매도만 / 매도와 매수 | 매도만. 매수는 2단계에 남김 | — |
| 주문의 출처 | 코어 매도 주문표(S7 줄이기·카드 EXIT·목표 비중이 있는 카드 TRIM) / 사장 할 일 장부 | 코어 주문표만(아래 3-1) | — |
| 상품 목록 | 보유 종목 전부 / 지정 종목 | 사장이 정함 | 사장 |
| 1회 크기 상한 | 계좌 비중 기준 | 사장이 정함 | 사장 |
| 하루 회전율 상한 | 계좌 비중 기준 | 사장이 정함 | 사장 |
| 노출 조건 | 제출 뒤 E가 내려가는 주문만 / 제한 없음 | E가 내려가는 주문만 | — |
| 주문 유형 | LOC / 그 밖 | LOC만(2단계와 같음) | — |
| 봉투 밖 | 2단계로 떨어짐 / 제출 안 함 | 2단계로(원문 그대로) | — |
| 유효 기간 | 무기한 / 기한 뒤 다시 확인 | 기한을 두고 다시 확인 | 사장 |
| 정지 스위치 | 새 제출 차단 / 미체결 정리까지 | 미체결 정리까지(f-trading-infra-gap-review 67행) | — |

첫 봉투를 매도로 좁히는 까닭: 잘못 나간 주문은 체결되면 되돌릴 수 없다. 위험을 줄이는 쪽은 틀려도 노출이 내려갈 뿐이고, 늘리는 쪽은 틀리면 손실이 커진다. 이것은 설계자 판단이고 시험으로 검증한 것이 아니다.

**부딪힐 수 있는 기존 결정.** 지금은 '자동 매도 없음'이 사장 결정이다(active-decisions.md ev-derisk b 행, 2026-10-13 · f-trading-infra-gap-review 30행 "자동 매도는 없다(사용자 결정 2026-10-01 S5/S7 …)"). 원래 결정의 자리는 하락 쪽 대응과 손실선이다: "하락 쪽 대응을 지금 바꿀지. 기본값은 현행 유지(자동 매도 없음)"(event-strategy-2026-10-13.md 22·145행), 고점 −30% 검토 규칙의 "자동 매도·매도 권고 없음"(loss-limit-review-s5-policy-proposal-2026-10-01.md 816~824행). 코어 주문표(S7 줄이기·카드 EXIT·TRIM)를 승인 없이 제출하는 것까지 덮는지는 원문에 없다. 그래서 3단계 안건에는 '매도 봉투가 자동 매도 없음에 걸리는가, 걸리면 봉투 범위만큼 다시 여는가'가 사장이 정할 첫 항목으로 들어가야 한다(exit1117-preregistration-2026-11-17.md 112행은 가격 기준 매도 규칙에 대해 같은 결정을 다시 열 항목으로 적었다). 이 메모는 그 결정을 바꾸지 않는다.

### 3-1. '사장이 이미 정한 행동'을 봉투에 태우는 두 길

- (a) **카드 목표 비중으로 옮기기(기존 길).** 사장 결정을 보유 카드의 TRIM·목표 비중으로 적으면 코어가 매도 주문표를 만든다(auto_core_tickets.py 965~982행). 매도 근거가 충족될 때만 나오고(800~806행), 한 번에 줄이는 크기는 근거의 세기로 정해진다: 강한 근거(공식 사실)면 차이 전부, 약한 단서 2종류면 최대 절반, 그 단서가 공통 규칙 C뿐이면 1/3이다(38·132~135행). 새 코드가 필요 없다.
- (b) **사장 할 일 장부를 직접 주문으로(새 길).** docs/claude/ceo-open-actions.json(지금은 알림용이고 코어가 읽지 않는다. 같은 파일 `note`)의 항목을 결정론 모듈이 주문으로 바꾼다. '한 번에'가 되지만 코어의 매도 근거 확인을 건너뛰고, 시스템에 수량 권한을 주는 결정이 따로 필요하다(지금 `quantity_authority = none`, constitution-v1.5.0.md 1001행).
- 권고: (a)를 먼저 쓴다. (b)는 2단계 실적 뒤 봉투를 정할 때 사장이 고른다.

## 5. 열리는 조건과 순서

```
['켜']  사장 직접 입력
   ↓
[1단계 실적]  오류 0으로 10거래일 또는 5건
   ↓
[T5 → 2단계]  사장 결정
   ↓
[2단계 20건 오류 0 + 대조 장치]
   ↓
[3단계 부품 안건(K3) + 봉투 결정]
   ↓
[3단계]  사장 별도 승인
```

- 조건 원문: automation-redesign 132~135행. 조건 칸은 "제안, 사용자가 정함"이라 사장이 바꿀 수 있다.
- **솔직한 거리**: 20건 조건은 주문표가 나오는 빈도에 달려 있다. 10월 말 기록으로 주문표는 그때까지 1건이었다(roadmap.md 27행). 언제 채워질지는 확인 필요이고, 이 메모는 날짜를 추정하지 않는다.
- 3단계를 여는 승인은 주문 도구 금지(Hard safety, CLAUDE.md 19행)를 바꾸는 일이라 사장 직접 입력으로 받는다(짝 문서 8절 4번과 같은 엄격한 읽기).
- 봉투를 넓히는 변경은 매번 사장 결정이다(권한·한도 변경 절차 — CLAUDE.md 66~82행. 결정 카드는 권한·한도 작업의 착수에 한하고 정책·상태 변경과 병합은 직접 입력·사장 PowerShell이다 — active-decisions.md btn-approval 행). 시스템은 스스로 넓히지 않는다(constitution-v1.5.0.md 530행).

## 6. 위험

- 자동으로 나간 주문은 체결되면 되돌릴 수 없다. 첫 봉투를 좁게 잡는 까닭이다.
- 키움 주문에는 클라이언트 주문 ID가 없어 중복을 서버가 막아 주지 않는다(f-trading-infra-gap-review 18행). 자동 제출에서는 우리 장부와 대조 장치가 유일한 방어다.
- PC 한 대에 달려 있다(19행). 제출 도중 멈추면 응답 불명이 되고, 그때는 다시 보내지 않고 대조한다(40~41행).
- 봉투는 판단의 품질을 올리지 않는다. 이미 정한 것을 빠짐없이 실행할 뿐이고, 무엇을 팔지는 여전히 코어·카드·사장 결정이 정한다.

## 7. 3단계를 기다리지 않고 지금 지시에 닿는 것 (새 제안 아님 — 이미 진행 중)

- 사장님 주문 할 일 알림(alert-strengthen-1117, 2026-11-17 08:56:42 KST 승인, 월~금 19:30 예약).
- 보유 카드 다시 쓰기(스레드 'LITE·SOXL·BE 보유 카드 다시 쓰기'): 사장 결정을 카드 목표 비중으로 옮길지 결정 카드로 올린다(3-1 (a)).
- '켜' 조건 판정(스레드 'T2 켜 조건 지금 충족 여부 확인'): 2026-11-17 판정은 미충족이고 가장 빠른 충족은 11/18 아침(조건부)이다(t2-on-check-2026-11-17.md 결론). 켜는 것은 사장이 직접 치는 "켜"다.
- 2단계 안건(짝 문서).
