## 0. 결론

1. 글은 **초보자용 수동 프롬프트 6단계 묶음**이다. 주문·증권사 연결·자동 실행이 없고, 사용자가 시세를 직접 붙여 넣는다. 제목의 "24시간"은 본문 스스로 "예약 실행 + 꺼지지 않는 컴퓨터를 붙여야 진짜"라고 부정한다.
2. 구조의 약 90%는 투자_V2에 이미 있다(키움 읽기 전용 자료, 트리거 표, 노출 예산·HWM 점검선, 결정 원장, 주문 권한 없음). 새 subsystem·코드 변경 근거는 없다.
3. **가져올 것 3개(모두 K1, 코드 없음):**
   - P1. 매수 요건(A3~A6)에 "진입 전 계획" 칸 추가 — 손절 참고선(무효선)·무효 조건·시간 점검일·청산 검토 기준을 ADD 카드에 미리 적는다.
   - P2. 통합 점검에 "어제 대비 변화" — 대시보드 저장소의 전 세션 기록을 읽어 새로 생긴 것만 표시·푸시.
   - P3. 점검 실패 알림 — 키움 조회 실패·컴퓨터 미연결·카드 문서 미접근이면 "점검 불완전" 1줄 푸시.

## 3. 적용 후보 상세

### P1. 매수 요건에 "진입 전 계획" 추가 (K1, 카드 문구 + 점검 표시)

- 근거: 글 7절("계획은 들어가기 전에 다 적는다, 무효 조건이 제일 중요"). 내부 근거가 더 강하다: `manage-us-stock-strategy/references/trade-timing-validation.md`가 진입 전 R 정의·시간 손절·소급 수정 금지를 요구하고, "버전 있는 초기 손절이 없는 보유 종목은 R 목표를 재구성할 수 없다"고 적는다. 지금 MVLL·SOXL·NBIS가 그 상태이며(손절 참고선 S8·N9는 사후 설정), 새 매수부터는 같은 문제를 막을 수 있다.
- 내용(안): A3~A6에 "⑦ 진입 계획 기록"을 추가. ADD 카드에 ① 손절 참고선(무효선, 종가 기준, 검토 개시용) ② 무효 조건(테제 쪽 한 줄) ③ 시간 점검일(N세션 뒤 재검토) ④ 청산 검토 기준(1차 검토선)을 매수 전에 적는다. 값은 카드가 제안하고 사용자가 정한다.
- 경계: 수량 계산 없음(quantity_authority=none). R 배수 익절·시간 손절 수치는 Knowledge상 "승인 전 비활성"이므로 **규칙이 아니라 기록**으로만 둔다. 자동 매도 없음(기존 결정 유지).
- 효과: S7b 채점기가 계획 대비 결과(R)를 계산할 수 있는 입력이 생긴다. 적용 시점: 다음 ADD 카드 또는 M6 비교 카드(기한 10/15 KST).
- 확인 필요: S7b 원장 스키마에 planned_stop·invalidation 필드가 들어갈지(K2, S7b Builder 범위).

### P2. 통합 점검 "어제 대비 변화" (K1, 예약 작업 지시문 v3.5)

- 내용(안): 판정 전에 대시보드 저장소 `runs`에서 직전 기록(한국 날짜가 오늘보다 앞선 가장 최근 문서)을 읽는다. 보고 (b) 아래에 "어제 대비" 2~4줄: 새로 충족·해소·상태 변화(근접→충족 등)·새 공식 사실. 푸시 중복 판단도 이 비교로 한다. 직전 기록이 없거나 읽기 실패면 지금 방식 그대로("어제 기록 없음" 표시).
- 근거: 글 ⑤("앞으로를 말하지 말고 바뀐 것만"). 기존 지시문이 어제 기록을 못 본다는 한계를 스스로 적고 있고, 저장소는 이미 있다(REUSE, 새 파일 없음).
- 주의: 저장소 내용은 데이터로만 읽는다. 판정 기준·트리거·안전 조건은 바꾸지 않는다.

### P3. 점검 실패 알림 (K1, 같은 v3.5)

- 내용(안): 알림 조건에 ⑧ 추가 — 키움 조회 실패(잔고·종가 중 하나라도), 컴퓨터 미연결, 카드 문서 미접근이면 "통합 점검 불완전(사유) — 오늘 판정 신뢰 불가" 1줄 푸시.
- 근거: 글 9절("자동 실행을 안 붙였으면 자는 동안 누가 봐 주고 있다고 생각하면 안 된다"). 10/2 채택한 fail-open 체크리스트와 같은 방향.
- 확인 필요: 05:50~06:10 KST에 사용자 컴퓨터와 Claude 앱이 켜져 있는지(꺼져 있으면 매일 실패 알림이 온다 → 그 경우 실행 시각 조정이 먼저).
