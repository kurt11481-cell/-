# 주문 지시 수령 과정 보완 검토 (트레이딩 유저 관점, 2026-10-09)

## 0. 결론
- 하루 2번 접점(아침 Cowork 1회, 저녁 키움 입력 1회)과 LOC 중심 구조는 유지한다. 사용자는 장중에 자므로 맞는 구조다.
- 고칠 곳은 저녁 입력이다. 지금은 사용자가 (a) 지시서가 어디 있는지 찾고 (b) 발행 뒤 푸시가 있었는지 기억하고 (c) 기준종가를 직접 대조하다 범위 밖이면 Cowork를 다시 열어야 한다. (d) 프리마켓이 이미 지시 가격 밖이어도 멈추는 항목이 없다.
- 보완 5개: 2-1~2-3은 표시·양식(K1)이라 다음 지시서부터 시험 가능, 2-4는 K3 후보(시범 뒤), 2-5는 사용자가 정할 규칙.

## 2. 보완안 (우선순위순, NO_CHANGE → SIMPLIFY → REUSE → ADD)

### 2-1. 넣을 지시는 전부 대시보드에 올린다 (K1, REUSE)
- 지금: `user` 상태는 사용자가 요청할 때만 기록(dashboard-order-panel 3절). SOXL-1은 대시보드에 없었다.
- 바꿈: 사용자가 "진행"을 고른 지시(공식·시범 공개·수동 결정)는 결정 직후 Cowork가 orders에 pending으로 기록한다. 저녁에 볼 곳을 대시보드 한 곳으로 만든다.
- 변경 위치: dashboard-order-panel 3절 `user` 비고, 4절 2번 문구. 화면 코드 변경 없음.

### 2-2. 가격 환산식을 카드에 넣는다 (K1, SIMPLIFY)
- 지금: "기준종가가 $142.40~$142.60 밖이면 Cowork에 하한 재계산"(SOXL-2) — 저녁에 Cowork를 다시 열어야 한다.
- 바꿈: 같은 산식을 곱셈 한 줄로 카드에 적는다. 예: "하한 = 키움 기준종가 × (1 − σ60) , 소수 둘째 자리 올림" + 기준종가 3~5개 값의 환산표. 산식은 그대로이고 사용자는 화면 숫자만 맞춘다.
- 남는 위험: 공식 종가가 들어오면 σ60도 조금 바뀐다. 근사 종가와 공식 종가 차이가 얼마 이상이면 재계산할지 기준은 확인 필요.

### 2-3. 입력 전 확인을 "기억"에서 "화면 숫자"로 (K1)
1. 오늘 아침 대조를 마쳤다(그대로).
2. 발행 뒤 푸시: 카드에 발행 시각(issuedAt)을 크게 보여 휴대폰 알림 시각과 비교하게 한다.
3. 키움 잔고·미체결(그대로).
4. **신규** 프리마켓 갭: 키움 현재가가 이미 하한(매도) 아래 또는 상한(매수) 위면, 넣기 전에 Cowork "재검토". 판정이 아니라 멈춤 신호다 — 그대로 넣으면 체결 가능성이 낮고 재발행 1회를 쓰게 된다. 넣을지는 사용자가 정한다.

### 2-4. 17:15 "입력 직전 점검" 예약 (K3 후보 — 시범 3회 뒤 K3-9와 함께)
- 키움 읽기 조회(실전계좌·real)로 기준종가·프리마켓가·잔고·미체결을 보고, SEC 수집·개장 전 기록에서 발행 뒤 새 항목을 확인해 "GO / 재검토" 1줄 푸시. 가격·수량은 계산하지 않는다(그건 K3-9).
- 이익: 2-3의 2·4번을 사람 대신 확인. 비용: 새 예약 1개(토큰, 8005 실패 때 fail-closed, PC 켜짐 필요).
- 조건: 2-1~2-3을 1~2회 써 보고도 저녁 확인 누락·실수가 있을 때만 추가한다(복잡도는 미충족 요구 + 검증 가능한 이익이 있을 때만).

### 2-5. 사용자가 정할 규칙 2개
- (a) 미입력(저녁에 못 넣음)이 재발행 1회를 쓰는가 — 설계 문서에 없다. 선택지: 쓰지 않음(시장 시험이 없었으므로) / 씀(같은 지시 반복 방지).
- (b) 위험 감축 매도에서 프리마켓이 이미 하한 아래일 때: 설계 문서 주문 유형 표에 "시장 급락 신호에 따른 축소(규칙 승인 뒤) → MOC"가 있으나 그 신호의 정의와 확인 시점이 입력 전 확인에 없다. SOXL-1이 이 경우였다. 가격·유형 규칙이라 K3.

### 2-5(a) 검토 — 미입력과 재발행 횟수 (2026-10-09 14:0x KST, 사용자 요청 "미입력 규칙 결정 검토")
- 기존 규칙: 7-3 "같은 결정의 재발행은 1회, 두 번 체결되지 않으면 카드 재검토(추격 방지 감쇠)", 14절 "재시도 상한 = 재발행 1회". 미입력이 이 1회를 쓰는지는 정의되지 않았다.
- 재발행 1회의 목적은 **시장이 가격을 거절한 뒤** 같은 결정을 쫓아가지 않게 하는 것이다. 미입력은 시장 시험이 없었으므로 목적과 맞지 않는다.

| 선택지 | 장점 | 단점 |
|---|---|---|
| ① 차감 없음 + 제한 (권고) | 운영 누락(잠, 이동, 키움 접속·8005 실패)이 결정 기회를 깎지 않는다. 위험 감축 매도는 시장 시험 2회를 지킨다. "재발행 횟수 = 시장 시험 횟수"라 미체결률·미입력률 통계가 섞이지 않는다 | 제한이 없으면 미루기 반복 → 아래 제한 3개로 막는다 |
| ② 차감 | 규칙이 가장 단순하다. 미루기 반복이 원천 차단된다 | 하룻밤 누락으로 기회가 반으로 준다. 감축 매도라면 노출이 그대로 남는다. 시장이 거절하지 않은 결정에 감쇠를 거는 셈이다 |
| ③ 사유별 3분류(누락·확인 중단·변심) | 가장 정확하다 | 상태 3개 추가는 복잡도 증가. 사유는 메모로 충분하다 |

- 권고 ①의 제한 3개:
  1. **자동으로 다시 나오지 않는다.** 다음 아침 대조에서 미입력으로 분류되면 사용자가 "다시" 또는 "종료"를 고른다. "종료"는 사용자 결정으로 기록하고 지시를 닫는다.
  2. **연속 미입력 2회면 그 결정은 종료하고 카드 재검토로 간다.** 이것으로 반복 횟수의 상한이 생긴다(14절 재시도 상한과 같은 역할).
  3. **다시 낼 때는 재발행과 같은 절차를 거친다.** 새 기준가로 관문(G0~G5, 매수는 R-REC1 포함)·옵션 층·위원회를 다시 본다. 매수 상한은 첫 지시서 상한 이하로 둔다(R-RI1과 같은 방향, 낮추기만).
- 사유는 상태를 늘리지 않고 outcome.note에 한 줄로 적는다(누락 / 입력 전 확인에서 멈춤 / 변심). 입력 전 확인에서 멈춘 경우는 그날 Cowork 재검토가 우선이다.
- 가장 강한 반대: 차감이 없으면 숙려 뒤 망설임이 습관이 되어 결정이 계속 이어진다. 대응은 제한 1(사용자가 매번 고름)과 제한 2(2회 상한)다.
- 분류: 7-3·K3-4의 빈칸을 채우는 규칙 후보. 사용자 결정 뒤 시범·수동 지시서에 적용하고, 공식 반영은 K3-4와 함께 Judge 뒤에 한다.
- **결정(2026-10-09 14:06 KST): 사용자 "권장안 적용" → ① 채택. 설계 7-3절 R-NE1, 13절 K3-4, 14절 재시도 상한 문구에 반영.**
- 근거 표본: 미입력 사례는 아직 0건(지금까지 3건 모두 입력 또는 지시 없음). 효과는 시범 기록으로 다시 본다.
