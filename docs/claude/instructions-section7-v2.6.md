프로젝트 기본 모델은 Opus 5.5(결과 품질 우선). 코디네이터는 스레드를 열 때 아래 표의 모델과 추론 노력을 알린다. 회사PC 폴더 스레드는 지정이 먹지 않고 기본 모델로 시작하므로, 표와 다른 모델이 필요하면 스레드가 일을 시작하기 전에 한 줄로 알리고 사장이 첫 입력으로 맞춘다. 일을 시작한 뒤에는 모델을 바꾸지 않고 새 스레드를 연다.
- 단순 확인·상태 조회·파일 찾기·설정 안내: Sonnet 5.5 · low
- 웹 조사·자료 정리·영상/PDF 요약·문서 초안: Sonnet 5.5 · medium
- 진단·원인 분석·코드 읽기·제안서 작성·개발 큐 지시문: Sonnet 5.5 · high
- 깊은 분석·전략 수립·로드맵·투자 판단 근거 검토: Opus · high
- 여러 스레드나 여러 달에 걸치는 큰 일의 기획·설계와 마무리 검수, 가장 어려운 종합 추론(여러 자료를 엮는 보유·매매 기준 검토, 전략 재설계, 마스터플랜, Opus 결과를 독립 재검토할 때, 사장이 Fable 지정): Fable 5.2 · high(그 위 노력은 쓰지 않는다). 사용 크레딧으로 청구되는 것이 확인되면 코디네이터는 Fable로 열지 않고 Opus · high로 대신한다(사장이 직접 지정한 경우는 그대로).
- 권한·K3·Judge·CLAUDE.md/헌법 개정·안전 검토: Opus · xhigh
- 예약이 깨우는 스레드: 옮겨 알리기 = Sonnet 5.5 · low, 정해진 순서 수집 = Sonnet 5.5 · medium, 판단이 들어가는 점검 = Opus · high
큰 일(전략 재설계, 새 예약·새 시범처럼 지시문과 연결표가 필요한 일, 여러 스레드에 걸치는 일)은 세 걸음으로 한다: ① 설계 Fable · high ② 구현 Opus · high(개발 큐는 지금처럼) ③ 검수 Fable · high 새 스레드. 세 걸음은 차례로 열고, 개발 큐 Judge와 CLAUDE.md 내장 재검토를 대신하지 않는다.
사장이 모델을 직접 지정하면 그 모델을 쓴다. 스레드는 첫 응답에서 길게 안내하지 않고, 시작 모델이 표와 다를 때만 한 줄로 알린다. 일이 커져 윗 단계가 필요해지면 "Opus 새 스레드 권장" 또는 "Fable 새 스레드 권장" 한 줄만 알린다. 작업 중 단계가 바뀌어 필요한 생각의 양이 위 표의 다른 줄로 옮겨 가면, 모델은 그대로 두고 추론 노력만 한 줄로 제안한다(올리기 예: "다음은 원인 분석이라 high가 맞습니다", 낮추기 예: "다음은 정리라 low로 낮춰도 됩니다"). 여러 턴 이어질 단계에서 한 번만 알리고, 짧은 단계와 예약이 깨우는 스레드에서는 알리지 않는다. 제안 뒤에는 기다리지 않고 지금 노력으로 계속한다. 다만 권한·K3·Judge·안전 검토 단계가 xhigh로 바뀌지 않았으면 fable-advisor 검토를 거친 뒤 마무리한다. 지금 모델로 맞출 수 없으면(예: Sonnet 스레드에 깊은 분석) 노력 대신 새 스레드를 권한다. 바꾸기는 사장이 한다. 프로젝트에서 /advisor가 안 되므로, 개발 큐 지시문 올리기 전·제안서 마무리 전·투자 판단 근거 정리 전·새 예약 지시문이나 사전 등록 고정 전·같은 문제 2번 실패 뒤에는 fable-advisor 스킬로 Fable 조언 작업자를 부른다(결과를 내놓기 전에 부른다). 애매하면 한 단계 낮게 시작한다. 동시 3개 이하, 작은 질문은 이 대화에서 바로 답한다. 추가 사용량 구매를 권하지 않는다. 주간 한도가 70%를 넘으면 큰 일은 초기화 뒤로 미루자고 한 줄 알린다. 이상하면 프로젝트 Pause.
