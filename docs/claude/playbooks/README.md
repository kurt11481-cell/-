## 1. 폴더
```
docs/claude/playbooks/<job>/
  SKILL.md        아래 2절 머리 + 본문 7요소, 300줄 이하
  files/INDEX.md  파일별 한 줄: 이름 · 용도 · 날짜 (스크립트·템플릿·참조 자료, 비밀 금지)
  checks.py       기계 검사 5~10개(모호한 품질어 금지), 실패 항목을 한 줄씩 출력
  notes.md        고침 기록: 날짜 · 무엇이 잘못 · 무엇을 바꿈(최신이 위)
  examples/       형식 예시만(매매 판단 예시는 넣지 않음 — 사후 편향)
```
고칠 때는 덮어쓰지 않고 판 번호 붙은 새 파일(예: SKILL.v2.md) — 덮어쓰면 해시 불일치로 교체 승인 전까지 작업이 멈춘다.

## 2. SKILL.md 머리 (필수 칸)
```
---
job: <id>
when: <사장이 실제로 칠 말 / 예약 시각>
inputs:            # E1 — 누가 쓴 파일을 읽나
  - <경로> (쓰는 작업: <작업 이름>)
outputs:           # E1 — 내 결과를 누가 읽나(소비자 최소 1개, 연결 규칙 analysis-linkage-map 0절)
  - <경로> (읽는 작업: <작업 이름>)
repeat_failure:    # E2 — 반복 실패 처리
  unit: <일|주>
  rule: 직전 결과 파일과 같은 실패가 연속 2회 → 결과 파일 첫 줄 "반복 실패 n회 — <원인 단계>" + 알림 1줄
  owner: 주간 팀장회의 → 연구개발팀 팀 처리(사장 확인으로 올리지 않음)
class: <일반 | 권한 관련(자동 코어 입력·주문표 표시에 닿음 → 해시 교체는 K3)>
---
```
- 모델 칸은 두지 않는다(모델은 scheduled-prompts/README.md 표 한 곳).
- E1: 이 플레이북이 생긴 작업의 analysis-linkage-map 행은 "playbooks/<job>/SKILL.md 머리 참조" 1줄로 바꾼다(원본 하나).
- E2: 결과 쓰기를 막는 규칙은 지금 그대로(하나라도 실패하면 막음, 매수 쪽 막힘·매도·위험 축소 알림은 막지 않음). 실패해도 실패 알림은 보낸다. 2개 넘게 실패하면 원인 단계를 함께 적는다.

## 4. 로더(예약 지시문)
- 지시문 = 절대 금지 + 플레이북 파일 전부(SKILL.md·files/·checks.py)의 sha256 목록 + "불일치면 실행하지 않고 실패 알림 1줄".
- 예약 실행은 자기 플레이북을 고치지 않는다. 개선 후보는 결과 파일에만 적고 Cowork가 새 판 파일로 반영 → 해시 교체는 사장 승인(권한 관련이면 K3).

## 5. 고침 루프
결함·사장 지적 → 그 일의 notes.md 1줄 + 가장 작은 수정(새 판). 같은 실수 2번째 → SKILL.md에 명시 금지 규칙.
