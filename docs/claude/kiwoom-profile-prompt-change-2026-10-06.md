# 키움 조회 profile 고정 — 예약 프롬프트 수정안 (2026-10-06, Cowork)

## 1. 근거 (오늘 실측, 읽기 전용 조회)

| 호출 | 결과 |
|---|---|
| `--profile 실전계좌` | 성공 (return_code 0), 브리지 실행 전·후 모두 |
| profile 없음 | 8005, 별칭 전환(`auth login` 1번) 뒤에도 8005 |
| `--mode real`만 | 8005 |
| `profile 실전계좌 + mode real + named true + format json` (현황판 프롬프트와 같은 조합) | 성공 (return_code 0) |

- 별칭 토큰 저장 시각(21:40:56)이 브리지 실행(21:43:59) 뒤에도 그대로 → 브리지는 토큰을 새로 받지 않고 재사용했다.
- 프로필 없는 조회가 쓰는 토큰 저장소의 정체와 원인(MCP 서버 환경설정 등)은 확인 필요.
- 현황판 마감 정리 프롬프트는 이미 "profile 실전계좌 + mode real 고정(빼면 옛 토큰으로 8005)"을 담고 있다. 이번 수정은 같은 규칙을 나머지 작업에 맞추는 것이다.

## 3. 삽입 문장 (7개 모두 동일)

```text
키움 조회 공통 규칙(2026-10-06): kiwoom_query를 부를 때마다 options에 "profile": "실전계좌", "mode": "real"을 반드시 넣는다(빼면 별칭 토큰과 다른 옛 토큰으로 호출되어 8005 인증 오류가 난다). 8005가 나도 auth·login·토큰 재발급 명령은 시도하지 않는다(다른 작업의 토큰을 무효화할 수 있다). 그 조회는 실패로 기록하고 이 작업의 기존 실패·점검 불완전 규칙을 따른다. 응답은 return_code가 0일 때만 값으로 쓴다.
```

문장 뒤에 빈 줄 하나를 두고 기존 문장을 그대로 잇는다. 그 밖의 문자는 바꾸지 않는다.

## 4. 적용 방법과 검증

1. 적용: 각 작업의 현재 프롬프트(예약 작업 상태에서 읽은 원문)에 3절 문장만 삽입해 update_trigger로 prompt를 교체한다. 교체 전후 길이 차이가 삽입 문장 길이와 정확히 같은지 확인한다.
2. 반드시 통합 점검(10/7 06:40)보다 먼저 적용한다. 나머지는 다음 실행 전이면 된다.
3. 적용 뒤 확인: 10/7 06:40 통합 점검의 점검 상태 ㉡ "키움 잔고(balance) 조회 성공"이 통과인지, 8005가 없는지.
4. 롤백: 삽입 문장과 빈 줄 하나를 지운다.

## 5. 위험·확인 필요

- 프롬프트 전체 교체이므로 삽입 외 변경이 없는지 길이·diff로 확인한다.
- 프로필 없는 조회가 왜 다른 토큰을 쓰는지는 미확인이다. 새 예약 작업·수동 호출도 같은 규칙을 따라야 한다(작업 생성·변경 체크리스트: analysis-linkage-map-2026-10-05.md).
- 서버의 "새 토큰 발급 시 이전 토큰 무효화" 규칙은 문서 근거가 없다(확인 필요).
