# 외부자료 검토 — AI 운영체제 대시보드 · AI 세컨드 브레인 (2026-10-05)

읽기 전용 검토. 대시보드 HTML·저장소·예약 지시문·정책·상태 파일은 바꾸지 않았다. order_authority=false.
자료: 사용자가 대화에 올린 PDF「AI 운영체제 대시보드 세컨드브레인」(5쪽, 작성자·출처 표기 없음).

## 0. 결론
1. 대시보드: PDF의 5구역(오늘 할 일·이번 주 마감·진행 중·막힌 업무·결정 필요)은 두 대시보드에 이미 있다. 가져올 것은 구역이 아니라 원칙 두 개 — "행동할 정보만 첫 화면에", "도입 전후를 숫자로 비교".
2. 도입 후보(모두 승인 전): A 통합점검 상세 구역 기본 접힘 · C 1주 사용 뒤 안 보는 구역 정리 · D 관제판 마감 지난 일 빨강 · E 효과 기준 기록. 새 기능·새 연동은 없다.
3. 세컨드 브레인: 별도 시스템은 필요 없다. PDF 4요소 중 3개는 이미 있다(외부 주장 원장, INDEX.md, 판단 기록장·채점기). 빈칸은 "시스템·정책 결정의 이유를 한곳에서 찾기" 하나 — INDEX.md에 "주요 결정" 절(포인터만)을 붙이는 것으로 충분하다(F).

## 1. 자료 요약 — 사실/해석/가설
- 성격: 개념 설명 자료. 수치·사례·출처 없음. 시장 주장 없음 → 외부 주장 원장 등록 대상 0건.
- 자료가 말하는 구성(사실로서의 내용): 대시보드 = 캘린더·이메일·할 일·프로젝트 문서 → 고객명·프로젝트명으로 연결 → 5구역. 세컨드 브레인 = 문서·회의록·아이디어·결정 → 핵심·이유·다음 행동 추출 → 과거 자료와 연결 → 검색해서 활용. 둘 다 "가장 작게 시작 → 1주 써 보고 확장".
- 해석: "많이 보여주는 게 아니라 지금 행동할 정보만 남긴다", "결정은 무엇을 골랐는지보다 왜, 무엇을 포기했는지까지".
- 가설(검증 없음): 시간 절약, 지연 조기 발견, 재조사 감소. 단 자료 스스로 전후 비교 기준(아침 파악 시간, 늦게 발견한 지연 수, 재조사 횟수)을 제시 — 이 부분은 채택 가치 있음.

실측:
- 통합점검 저장 기록: 10/2 23,700B → 10/3 41,169B(+74%, 관심 명단 확장 영향 포함). '확인 필요' 14개(분량은 직전 기록의 약 2.8배). 상세 6구역 중 기본 접힘은 saveticker 1개뿐, 나머지 5개(트리거 상세·매수 요건·계좌 상세·시장/뉴스·확인 필요)는 기본 펼침.
- 개발 관제판: 작업 60개(끝남 36·기다림 15·예정 8·보류 1). 마감 지난 일 현재 0건.
- 관제판 코드: 마감이 지나면 "마감 N일 지남"이 정상 색(초록)으로 나온다(countdown()이 지난 날짜를 'ok'로 반환, renderNext에서 마감에도 그대로 사용). 재개 날짜에는 맞는 색, 마감에는 틀린 색.

## 3. 도입 후보 (승인 전, 한 번에 하나)
| # | 대상 | 내용 | 등급 | 비용 | 근거 |

조건부(지금은 안 함):
- B 결정 항목 "N일째 미결" 표시(지시문 문구). 지금까지 결정은 하루 안에 닫혔다(MU U2: 10/2 결정, 10/3 새 근거로 재상정 → 10/3 결정, 카드 470행). 같은 결정이 2회 넘게 미결로 남으면 그때 추가.

하지 않음:
- 두 대시보드를 한 화면으로 합치기 — 개발 작업과 투자 판단은 권한·성격이 다른 영역(커널 §7 경계 유지). 둘 다 사이드바 고정이라 이동 비용이 작다.
- 캘린더·이메일 연동 — 이 시스템의 "일정"은 시장 일정·재개 조건이고 이미 표시된다. 연동은 토큰·보안 비용만 늘린다.
- 종목 기준 자동 묶음 화면(종목 요약판) 지금 만들기 — 라이브러리 설계 3단계 조건 그대로. 10/6 MVLL 카드 갱신 때 s-library 바이트 비교와 함께 판단.

## 5. 세컨드 브레인은 필요한가
결론: 별도 시스템은 필요 없다. 2026-10-03 라이브러리 설계의 "부분 타당" 판정과 같은 결론이고, 그 뒤 실제로 갖춰진 것이 더 많다.

| PDF 요소 | 이미 있는 것 | 빈칸 |
|---|---|---|
| 모으기 | docs/claude 95개 항목(md 81개), 외부자료 .md 캐시, SAVE web-feed | 없음 |
| 핵심·연결 | external-pdf-intake → 외부 주장 원장(확인 조건·기한), INDEX.md(현행 문서 포인터), 표준 머리말(md 81개 중 15개) | 머리말 적용률 낮음(늘릴 필요는 확인 필요) |
| 결정과 이유 | 투자 판단: decision_journal.json + 채점기(S7b). 종목 판정: 카드 문서 '사용자 결정' 절 | 시스템·정책 결정: P4 §9 진행 기록·설계 문서 결정 절·관제판 기록·통합점검 지시문 제외 목록·프로젝트 메모리에 흩어져 있음 |
| 검색·활용 | grep + INDEX 읽기 순서 규칙(라이브러리 설계 3절) | 없음 |

F. 빈칸 대응(제안, REUSE — 새 파일·새 작업·새 예약 작업 없음):
- INDEX.md에 "주요 결정" 절 추가. 한 줄 = 날짜 | 주제 | 채택 | 버린 대안 | 이유 한 줄 | 재검토 조건 | 근거 경로. 내용은 복사하지 않고 포인터만.
- 범위: 다시 논의된 적이 있는 정책 흐름(손실한도·노출 1.0x→1.32x→1.55, 매매 근거 원칙, 외부 주장 강도 0)부터 10~15줄. PDF "프로젝트 하나로 시작"과 같다.
- 갱신: 정책·카드 결정 때만 1줄(수동). 자동화하지 않는다.
- 붙일 곳: 관제판 s-library 작업(10/6 재개, 근거 문서 analysis-library-design-2026-10-03.md)의 다음 단계.
- 효과 확인: 1개월 뒤 "이미 정한 것을 다시 논의한 횟수", "결정 이유를 찾느라 연 문서 수".
- 조건부: 통합점검 지시문의 '사용자 결정 제외 목록'이 결정 기록만을 위해 지시문 버전을 2회 이상 올리게 하면, 그때 수락된 결정만 담는 판정 기록으로 옮긴다(쓰기는 Cowork 사람 수락 뒤만). 지금까지는 기능 변경에 묶여 함께 바뀌었다.

## 6. 왜 틀릴 수 있나
- 첫 화면 접기로 상세(예: 매수 요건 막힘 사유)를 놓칠 수 있다 → 결론·결정 칸에 요약되는지 1주 확인(C와 같이).
- 결정 위치표가 또 하나의 유지 부담이 될 수 있다 → 정책·카드 결정 때만, 포인터만.
- 효과 평가가 주관적일 수 있다 → 숫자(주간 점검 발견 수, 재논의 횟수)를 같이 본다.
- PDF는 일반 업무용 개념 자료라 투자 시스템의 권한·증거 경계를 다루지 않는다. 연결·요약은 캐시이지 근거 등급을 올리지 않는다(라이브러리 설계 5절).

## 7. 확인 필요
- S7b 카드 판단 항목에 '버린 대안·검토일' 칸이 있는지.
- 통합점검 화면에서 실제로 보는 구역(사용자 확인, C).
- 예약 실행 1회당 토큰 사용량(기존 확인 필요 그대로).
