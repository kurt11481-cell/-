## 결론
- **명세에는 모의투자 도메인(`https://mockapi.kiwoom.com`)이 미국주식 API에도 적혀 있다.** 그러나 **미국주식 주문·조회가 모의에서 실제로 되는지, 앱키가 실전과 다른지, 모의 계좌를 어떻게 얻는지는 확인 필요** (명세·외부 글에 근거 없음).
- 실제로 확인하려면 모의 앱키로 `mockapi.kiwoom.com`에 토큰을 받아 미국주식 조회 1건을 해 봐야 한다. 이는 사용자가 모의투자 신청·앱키 발급을 해야 가능하므로 **T5 질문 때 사용자 결정 1건**("모의 계정")으로 이미 분류돼 있다. 지금은 하지 않는다.

## 근거 (명세 조회, 10/12)
| API | 명세의 운영 도메인 | 명세의 모의투자 도메인 |
|---|---|---|
| au10001 접근토큰 발급 | https://api.kiwoom.com | https://mockapi.kiwoom.com |
| ust20000 미국주식 매수 주문 | 같음 | 같음 |
| ust21050 미국주식 원장 미체결 | 같음 | 같음 |

- 명세 검색에서 "모의", "모의투자"로는 API별 지원 여부를 알려주는 항목이 나오지 않는다(필드 검색 결과 0건). 즉 명세는 도메인만 적고 **TR별 지원 여부는 말하지 않는다**.
- 외부 해설 글(algolab.co.kr, 2026)도 TR별 모의투자 지원 여부·모의 앱키 분리·모의 계좌 신청 방법을 다루지 않는다고 밝힌다(WebFetch 확인).

## 부수 발견
- ust21050 명세의 **응답 예시**에 미체결 "있음" 모양이 있다(`result_list` 한 줄: `ord_no`, `orig_ord_no`, `ord_stat: 접수`, `ord_remnq` 등). 명세 필드표에는 없는 `frgn_ord_id`가 예시에만 보인다. 이는 **문서 예시일 뿐 실계좌 실측이 아니다** → C4(저녁 읽기 관측)에서 실제 모양을 확인한다. 어댑터가 이 필드를 쓰지 않으므로 지금 영향은 없다(확인 필요: 어댑터 SCHEMA_MISMATCH 검사가 예시 밖 필드에 걸리는지).
- 주문 응답(ust20000)에는 `ord_no`만 있고 클라이언트 주문 ID 입력은 없다(검토 문서 발견 1 재확인).

## 하지 않은 것
키움 호출 없음 · 토큰 발급 없음 · 모의 앱키 사용 없음 · 코드·정책 변경 없음.
