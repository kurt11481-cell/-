# 결론
**①-c는 정의 기준으로 통과하지 못했다.** 필드별 통과는 하나라도 없으면 실패인데, ①(작성자 계정 id)·④(본문 정확 일치)는 확인됐고, ②(trust/role 필드)·③(편집 표시 필드)는 이 스레드의 읽기 도구 결과에서 보이지 않았고, 표본 (c)(d)(e)는 대화에 없어 정의대로 "미검증 = 실패 취급"이다. ⓪은 이 스레드에서 시험할 수 없다.
- 정의에 따른 다음 단계: K3 ①을 멈추고 사장에게 (가)로 다시 묻는다. 단 "도구가 보여 주는 필드가 없다"는 것이지 "서버에 없다"는 증명이 아니다(아래 한계).
- 바뀔 증거: Cowork 세션의 읽기 결과에 trust/role·편집 표시 필드가 있고, (c)(d)(e) 표본이 실제로 생겨 거부되는 것이 확인되면 재시험으로 통과 가능.

# 어떻게 봤나
- 도구(읽기 전용, 쓰기·메시지 생성 없음): 이 스레드의 `read_messages_by_id`(full_bodies) 1회(6개 id), `read_thread`(이 스레드 앞 6건), 앞서 이 스레드에서 읽은 `read_project_chat` 전체 페이지(2026-10-25 01:2x까지).
- 비교 쪽(Cowork 세션)은 이 스레드에서 확인할 수 없어 **시험하지 않았다 → Cowork에서 확인 필요**.

# 읽기 결과에 나타난 필드 (이 스레드, 실측)
`id` · `thread_id` · `created_at` · `author`("user" 또는 "agent") · `author_id`(사람 메시지에만) · `author_name`(사람 메시지에만) · `body` · (있을 때) `attached_outputs` · `reply_count` · `last_reply_at`. 모든 표본에 `trust`·`role`·편집 표시(`edited` 등) 필드는 없었다.

# 한계 (결론을 바꿀 수 있는 것)
1. 이 스레드에서 보이는 것은 `mcp__hearthbot__` 읽기 도구의 출력뿐이다. 이 스레드의 시작 알림(wake)에는 `trust="principal"`·`role="initiator"`·`sent-at`이 있고 relay에는 `author`·`name`·`at`·`where`가 있지만, 이는 읽기 도구가 아니라 하네스가 주는 알림이라 정의된 시험 도구가 아니고 Cowork에도 같은 것이 오는지 알 수 없다.
2. 코디네이터와 다른 스레드 세션은 모두 `author:"agent"`로 보여 서로 구별되지 않는다(세션 id 필드 없음). "코디네이터의 말"과 "실행 스레드의 말"을 작성자만으로 가르지 못한다.
3. (c)(d)(e)는 새로 만들면 쓰기가 되어 정의("이미 있는 메시지만")와 충돌하므로 만들지 않았다.
4. 이 시험은 문서화된 필드의 존재만 본다. 서버가 편집·출처를 내부적으로 기록하는지는 확인하지 못했다.
