# v2.6.5 Kiwoom Replay Hardening

## Scope

This patch hardens the read-only Kiwoom candidate-Primary validation path. It
does not activate Kiwoom Primary. yfinance remains Primary, Kiwoom remains
`SHADOW_NOT_YET_OPERATIONALLY_ACCEPTED`, Codex Web remains conflict fallback,
and `order_authority=false`.

## Starting point

- origin/main: `834a68348ae2a17d746a70564bcfcc6b1090b26c`
- Previous replay: 20 sessions, 11 tickers, 220/220 Raw matches, 0/220 Kiwoom
  technical validations, 29/31 fault cases.
- Previous missing faults: single-session lock collision ownership and
  Adjusted-series conflict.
- Historical point-in-time strategy bundles did not exist and were not
  fabricated.

## Implemented controls

- Atomic owner-token locks; foreign and uncertain locks remain unchanged.
- TTL recovery only for a same-host owner proven dead, with atomic quarantine.
- Official `usa06012` continuation through `cont-yn` and `next-key`.
- Versioned 252-bar minimum, bounded pages, pacing, retries, and no-progress
  policy.
- Chronological deduplication, conflicting-duplicate rejection, future-bar
  rejection, and page provenance.
- Local deterministic Kiwoom EMA, ATR, RSI, MACD, RVOL, and timing decisions.
- Separate Raw, adjustment-basis, Adjusted, indicator-shadow, and decision-flip
  results.
- Separate `MARKET_DATA_PROVIDER_REPLAY` and
  `FULL_STRATEGY_CONTEXT_REPLAY` statuses.
- Forward-only append-only point-in-time context checkpoints with hash chains.
- A current-session read-only dry run that cannot deliver alerts or mutate
  runtime.
